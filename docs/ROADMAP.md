# 제품 로드맵 / 기능 기획 노트

상용 전자액자(Aura · Nixplay · Skylight · Pix-Star, 그리고 구글 Nest Hub · 삼성 The Frame)와
비교한 기능 격차 분석과 향후 개발 우선순위 정리. 핵심은 "어떤 기능이 없느냐"보다
**"이 제품의 정체성을 결정하는 한 가지 결정"**이다.

## 화면 용어 (문서·대화 공통)

혼동을 막기 위해 화면을 아래 이름으로 부른다.

| 이름 | 대상 | 경로 / 파일 |
|---|---|---|
| **wepic 홈페이지** | 첫 진입 랜딩(**상단 가로 메뉴** + 배너 + 안내 프레임) | `/` · `index.html`의 `#home-shell` |
| **wepic 메인화면** | 로그인 후 내 사진을 보는 슬라이드쇼 + 우측 설정 패널 | `index.html`의 `#screen-slideshow` · `app.js` |
| **wepic 공유화면** | 공유 링크로 로그인 없이 보는 화면 | `/f/<id>` · `share.html` · `share.js` |
| **wepic 관리자** | 화면관리·회원관리·PIN번호관리·Default 정보관리 (관리자 진입 시 **좌측 하위 메뉴**) | `index.html`의 `#admin-side-menu` |

>
> ↳ **홈 비주얼 개선** — AI 생성 홍보 이미지를 **원본 그대로(선명하게)** 화면 전체
> 배경으로 깔고, 좌측 메뉴·우측 안내 패널을 **반투명 유리(glass) 카드**로 얹음
> (전체 어둡게 처리는 없애고, 로고·글씨 뒤쪽만 국소적으로 대비 확보 →
> "로고 아래가 너무 어둡다" 문제 해결). 배경 위 가독성을 위해 **메뉴 글씨·단계 안내를
> 흰색**으로, 노란 안내 박스는 어두운 글씨로 수정. 등록 패널의 메일 버튼 제거.
>
> ↳ **인프라: Cloudflare Workers 이전(진행 중, 배포 디버깅 단계) + 저장소 정리** —
> Render 무료 플랜의 ephemeral 파일시스템 때문에 sleep/재배포 시 공유 파일이 사라지는
> 문제를 해결하기 위해 백엔드를 **Cloudflare Worker로 포팅**(세션=Workers KV, 공유
> 사진=R2 버킷 `wepic-shares`, 만료정리=Cron 매시간). 프론트엔드(`web/public`)는
> 그대로 재사용 → 서버가 자거나 재배포돼도 **공유 링크가 영구 유지**되는 것이 목표.
> 코드(`cloudflare/index.js`)와 `wrangler.toml`(저장소 루트, Cloudflare가 루트 설정을
> 기대하는 것을 확인 후 이동) 작성 완료, KV 네임스페이스 연결 완료. **아직 진행 중**:
> GitHub 연동 자동배포의 빌드 설정(Build/Deploy command) 및 시크릿
> (`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`SESSION_SECRET`) 등록을 맞추는 중 —
> 첫 배포 시도에서 Cloudflare가 예전 `renderer/`(Electron UI)를 정적 자산으로 자동
> 감지해 "정적 자산 전용" 상태로 잘못 설정된 것을 발견해 루트 설정으로 교정.
> 배포 성공 후 실제 로그인·공유 동작 검증이 남음. 동시에 더 이상 쓰지 않는
> **Electron 데스크톱 앱(main.js·preload.js·src/·renderer/·실행용 .bat·루트 package.json)
> 전체 제거**로 저장소를 웹(web/) + Cloudflare(cloudflare/) 중심으로 정리.

## 최근 구현 내역 상세 (로드맵 항목 밖에서 추가로 처리한 것들)

아래는 위 요약에 다 담기지 않은, 실제로 구현·수정했지만 원래 로드맵 항목엔 없던 것들이다.
(향후 유지보수 시 "이미 되어 있는지" 헷갈리지 않도록 기록)

- **🐞 카카오·네이버 회원의 "수정저장"이 로그인 화면으로 튕기던 버그 수정(2026-08-08)** —
  `POST /api/share`가 입구를 **`requireLogin`(구글 사진 API 토큰 필수)** 으로 막고 있었다.
  카카오·네이버 회원은 구글 토큰이 없으므로 401 → `api()`가 로그인 패널로 보내고, PIN·제목
  등 아무것도 저장되지 않았다. My사진관리에서 wepic을 열어 고칠 때(`?frame=`) 이 경로를 탄다.
  - 입구를 **`requireMember`(회원이면 통과)** 로 바꾸고, 구글 토큰은 **"구글에서 새로 받아올
    사진이 있을 때"만** `shareCreate` 안에서 확인한다. 이미 R2에 있는 사진만 다시 저장하는
    경우(=PIN·제목만 수정)에는 토큰이 필요 없다.
  - 새로 받아올 사진이 있는데 토큰을 못 얻으면 예전처럼 401로 알린다 — 조용히 건너뛰면
    새로 고른 사진이 소리 없이 사라진다.
- **🐞 My사진관리의 대표사진이 전부 깨져 보이던 버그 수정(2026-08-08)** —
  `canViewShare()`가 "만든 본인"을 **세션의 액자 목록(`frames`)** 으로만 판정했는데,
  세션은 로그인할 때마다 `frames: []`로 새로 만들어진다. 그래서 다시 로그인하면 PIN이 걸린
  내 액자의 사진이 **본인에게도 401**이 되고, 목록의 `<img>`가 전부 깨졌다.
  (목록 자체는 `ownerUserId`로 뽑는데 사진 접근만 `frames`로 판정해 어긋난 것)
  - 판정 기준을 **`ownerUserId`(D1 회원 id)** 로 맞췄다. 익명·다른 회원은 그대로 401이다.
  - 대표사진을 못 읽는 경우(동영상만 있는 액자 등)에는 "깨진 이미지" 아이콘 대신
    빈 회색 칸으로 남긴다.
- **🐞 `/api/status` 한 번 실패하면 로그인 버튼이 전부 "(준비중)"으로 죽던 문제(2026-08-08)** —
  실패 시 `{loggedIn:false}`로 대체되면서 `availableProviders`가 사라져, **눌리는 버튼이
  하나도 없는** 상태가 됐다(모바일에서 발생). 서버·배포는 정상이었고 화면 쪽 문제였다.
  - `/api/status`를 3번까지 재시도하고, 그래도 실패하면 **직전에 확인해 둔 목록
    (localStorage)** 을, 그것도 없으면 **전부 켠 상태**로 그린다 → 로그인이 죽지 않는다.
  - 실패했을 때만 "연결 상태를 확인하지 못했습니다" 안내를 띄운다.
  - `styles.css` / `app.js` / `share.js`에 `?v=` 버전을 붙여 예전 캐시가 남아도 새 파일을 받게 했다.
- **링크 카드 표지를 공개 여부와 상관없이 하나로 통일(2026-08-08)** — 예전에는 전체공유만
  **원본 사진 그대로**, PIN이 걸린 것만 흐린 표지를 써서 같은 wepic도 카드 모양이 달라졌다.
  이제 **언제나 `<id>/og.jpg`**(첫 사진을 살짝 흐리게 + 왼쪽 아래 wepic 로고, 1200×630)를 쓴다.
  - 표지가 아직 없는 예전 wepic은 **주인이 열기만 해도** 화면이 조용히 만들어 올린다
    (`ensureOgCover`) — "수정저장"을 따로 누르지 않아도 카드가 새 모양이 된다.
  - 표지를 못 만든 경우의 대체는 **원본이 아니라 로고**다(PIN을 걸어둔 사진이 새지 않도록).
- **"수정저장" 안내 문구를 "수정되었습니다"로 간결하게(2026-08-08)** — 무엇이 반영됐는지는
  화면(사진·PIN·주소)에 그대로 보이므로 길게 나열하지 않는다.

- **정보 패널(우측) UI 정리** — 패널이 스크롤되지 않아 하단 항목이 안 보이던 문제 수정
  (`overflow-y: auto`). 전환 간격을 슬라이더 → **리스트박스(select)**로, 전환 효과를
  셀렉트 → **라디오 버튼**으로 변경. 배경음악의 "Youtube연결" 버튼 제거하고
  재생/일시정지 토글 버튼을 링크 입력창의 ✕ 버튼 옆으로 이동.
- **재생 진행 표시(progress bar)** — 메인 슬라이드쇼·공유 보기 화면 하단에
  "현재 사진 / 전체" 비율을 나타내는 아주 희미한 진행바 추가(참고용, 눈에 띄지 않게).
- **공유 보기 화면(`/f/<id>`) 개선**:
  - 배경음악 **기본 무음** 자동재생(곡 제목만 확보) → ▶ 버튼으로 소리 on/off,
    곡목은 소리 여부와 무관하게 우측 하단(날짜 아래)에 상시 표시.
  - 링크를 **만드는 시점**의 슬라이드쇼 제목·전환 간격·전환 효과를 공유 화면에도
    그대로 반영(매니페스트에 함께 저장).
  - 공유 링크 **24시간 자동 만료(TTL)** + 만든 사람이 **즉시 폐기**할 수 있는 버튼.
  - 로그인 없이 받은 사진(구글 포토 "공유"로 유입, PWA)도 **`/api/share/blob`**로
    공유 링크를 만들 수 있게 지원(브라우저가 이미 든 파일을 그대로 업로드, 동영상은 제외).
- **PWA 다듬기** — 아이콘을 SVG 전용에서 **PNG(192/512) 추가**해 안드로이드 "앱 설치"가
  뜨도록 수정, 이후 아이콘 교체가 기존 설치 앱에 반영되도록 **파일명 버전업
  (`icon-*-v2.png`)**으로 캐시 무효화.
- **동영상 썸네일 예외 처리** — 정지 프레임 로드가 간헐적으로 실패할 때 깨진 이미지
  아이콘 대신 재생 배지만 보이는 빈 박스로 대체.
- **Cloudflare Workers 서브도메인 변경(2026-07)** — `wepic-live.garzette.workers.dev` →
  **`wepic-live.wepiclab.workers.dev`**로 변경. `wrangler.toml`의 `BASE_URL`,
  `cloudflare/README.md`, 이 문서의 참조를 모두 갱신.
- **관리자 "wepic 메인화면 열기" 완전 편집 가능화(2026-07)** — 기존엔 읽기 전용
  미리보기였으나, 이제 그 액자를 관리자 세션에 편입시켜(`POST /api/frames/:id/select`가
  관리자면 자동 편입) 사진 추가/제외·PIN 변경·"링크변경 반영"까지 실제로 동작하도록 수정.
  `/api/share`에 **기존 파일 그대로 유지(carry-forward)** 로직을 추가해, 다시 손대지 않은
  사진은 구글 재다운로드 없이 보존되게 함(Express·Worker 동일). 자세한 내용은 위 #10 참고.
- **기존 파일 재사용 방식 개선(2026-07)** — 유지하는 항목은 **파일 이름(R2 키)을 바꾸지 않고
  그대로 재사용**한다. 예전처럼 번호를 다시 매기며 복사하면 큰 동영상을 메모리에 올려야 하고,
  번호가 서로 교차할 때 아직 읽지 않은 파일을 덮어쓸 위험이 있었다. 새로 받는 항목만 남는
  번호를 쓰고, 이번 저장에 쓰이지 않은 예전 파일만 정리한다.
- **새 화면은 Default 값으로 시작(2026-07)** — 타이틀·배경음악을 브라우저(localStorage)에
  저장하던 것을 없앴다. 새 화면은 관리자 **Default 정보관리** 값으로 시작하고, 기존 액자를
  선택하면 그 액자에 저장된 제목·음악·전환설정을 복원한다(`/api/frames` 응답에 해당 값 추가).
- **메인화면 진입 시 "새 액자"로 시작(2026-07)** — 진입할 때마다 액자 선택을 해제해
  (`POST /api/frames/deselect`) 이전에 만든 액자를 실수로 덮어쓰지 않게 했다. 기존 액자를
  이어서 쓰려면 액자 목록에서 고르면 된다. `ensureFrames`도 남은 액자를 임의로 자동
  선택하지 않는다(지워진 액자를 가리킬 때만 해제).
- **wepic 공유화면 우측 하단 캡션 색상 조정(2026-07)** — 날짜·곡목 표시가 흰색이라 너무
  눈에 띄어서, 옅은 회색(`rgba(200,200,200,0.55)`)으로 바꿔 덜 두드러지게 함.
- **내 회원정보 화면(2026-07)** — 상단 메뉴가 로그인 전에는 "🔑 로그인", 로그인 후에는
  **"👤 이름"** 으로 바뀌고, 누르면 회원정보 패널로 간다. **이름과 이메일을 수정할 수 있고**
  (`PUT /api/me`) 로그인 방식·권한·가입일·최근 로그인은 읽기 전용이다.
  저장하면 상단 메뉴 이름도 즉시 바뀐다.
  - 이메일은 **연락·표시용**일 뿐 로그인·권한 판정에 쓰이지 않는다(로그인은
    `provider`+`provider_sub`, 관리자는 `users.role`). 그래서 이메일을 바꿔도 남의 계정이
    되거나 권한이 올라가지 않는다. 카카오처럼 제공자가 이메일을 주지 않는 경우를 위해
    **비워두는 것도 허용**한다.

## 가장 중요한 결정: 원격 사진 공급 (제품의 성패를 가름)

상용 전자액자가 파는 것은 "사진 보는 기기"가 아니라 **"떨어져 사는 가족이 부모님 액자에
사진을 원격으로 계속 보내주는 경험"**이다. Aura · Skylight의 리뷰가 극찬받는 이유의 90%가 이것.

현재 제품은 여기서 두 가지가 막혀 있다:

- **자동 동기화 없음**: 새 사진을 넣으려면 수동으로 "다시 선택" (Picker API 구조적 한계)
- **가족이 각자 보낼 수 없음**: 로그인한 한 계정의 사진만 표시

> ✅ **1차 진전 (PWA 공유 타깃 구현 완료)** — 앱을 PWA로 만들어 안드로이드에서
> 구글 포토 등의 "공유" 대상 앱으로 등록되게 했다. 가족이 폰에서 사진/동영상을
> **공유 → Wepic Live**로 보내면 로그인 없이 바로 재생된다. 단, 안드로이드
> Chrome 전용·PWA 설치 필요·HTTPS 필요이며, 자동(무설정) 동기화는 아니라 아래
> 방향(C/B)의 대체가 아닌 보완 진입로다.

이 둘은 뿌리가 같고, **아키텍처 선택**이 필요하다:

| 방향 | 방법 | 장단점 |
|---|---|---|
| **A. 구글 Ambient API 파트너 승인** | 인물/앨범 자동 동기화 | 진짜 자동, but 파트너 심사 통과 어려움 |
| **B. 자체 업로드 백엔드 구축** | 가족이 내 사이트에 사진 업로드 → 액자가 표시 | 완전한 제어(공유·캡션·다중액자), but 저장소 비용·개발량 큼 |
| **C. 구글 공유앨범 활용** | 가족이 공유앨범에 추가 → 액자가 그 앨범 표시 | 지금 구조에 가장 가깝고 저비용, but 사용자가 공유앨범 세팅 필요 |

**추천: C → B 순의 단계적 접근.** 우선 C(공유앨범 연동 + 주기적 자동 새로고침)로
"자동 동기화 + 가족 공급"을 저비용으로 구현해 시장 반응을 보고, 반응이 좋으면
B(자체 백엔드)로 넘어가는 것이 리스크가 낮다.

## 중간 난이도 — 감성/참여 기능

7. **"몇 년 전 오늘"** — 오늘 날짜의 과거 사진 우선 노출. 이미 촬영일 데이터가 있어 구현 쉽고 감동 큼.

9. **동영상 · 움직이는 사진 재생** — ✅ **동영상 재생 구현 완료**(종료 시 자동 전환,
   `/video` 프록시로 Range 지원). **동영상 소리 재생 옵션**(기본 ON): 켜면 소리 있는
   동영상 재생 + 재생 중 배경음악 자동 정지, 끝나면 음악 복귀. 끄면 음소거 재생(배경음악 유지).
   소리 자동재생이 막히면 음소거로 폴백. 움직이는 사진(Motion Photo) 재생은 아직 미구현.
   - ✅ **wepic 공유화면에서도 동영상 재생**(2026-07 추가) — 예전에는 공유 링크에 사진만
     담겨(클라이언트가 동영상을 걸러냈다) 메인화면에서 보이던 동영상이 공유화면에서는
     사라졌다. 이제 **동영상 원본을 공유 저장소에 함께 저장**해 재생한다:
     `/api/share`가 구글 원본(`=dv`)을 **스트림으로** 디스크/R2에 저장하고(메모리에 안 올림),
     매니페스트 항목에 `type: 'video'` · `videoUrl`을 남긴다. 정지 프레임(포스터)도 항상
     저장해 재생 전·실패 시 보여준다. 공유화면(`share.html`/`share.js`)에 `<video>` 레이어를
     추가해 재생하고, 끝나면 다음 항목으로 넘어간다(재생 중에는 전환 타이머 정지).
   - **왜 파일을 저장해야 하나**: `/video` 프록시는 로그인이 필요하고 구글 원본 URL도
     사용자 토큰이 있어야 열려서, 로그인 없는 공유화면에서는 쓸 수 없다.
   - Cloudflare Worker의 R2 서빙에 **HTTP Range(206) 지원**을 추가했다 — 없으면 iOS·사파리가
     재생을 거부하고 탐색도 안 된다. mp4/mov/webm MIME 타입도 함께 추가.
   - **크기 제한**: 동영상 1개당 기본 100MB(`MAX_SHARE_VIDEO_MB`). 넘거나 저장에 실패하면
     그 항목은 **정지 이미지로만** 담기고 공유 자체는 정상 생성된다.
   - 구글 포토 "공유"로 받은 사진(`/api/share/blob`) 경로는 여전히 사진만 지원한다.
   - ✅ **재생 대기 로직 수정(2026-07)** — 촬영 원본 그대로인 동영상은 메타데이터(`moov`
     박스)가 파일 맨 끝에 있는 경우가 많아(폰 카메라 기본 저장 방식), 파일이 클수록
     재생 가능해지기까지 시간이 더 걸린다(브라우저가 끝부분을 한 번 더 Range 요청으로
     받아와야 함). 예전 코드는 `play()`가 한 번 거절되면 1.5초 뒤 바로 "재생 불가"로
     보고 다음 항목으로 건너뛰어, 이런 동영상이 항상 먼저 스킵되는 문제가 있었다.
     이제 `canplay` 이벤트가 올 때까지 넘어가지 않고 재생을 계속 시도하며, 실제로
     건너뛰는 것은 재생 종료·진짜 디코딩 실패·15초 정체 타임아웃뿐이다
     (`web/public/share.js`).
10. ✅ **다중 액자 관리** _(구현 완료)_ — 한 계정으로 여러 액자(거실 · 부모님댁) 다른 사진 세트를
    **각각 이름 붙여 만들고, 선택해서 전환하고, 각각 계속 갱신**하며 운영할 수 있다.
    - wepic 메인화면 공유 블록에 **액자 선택 UI**(선택 목록 + "새 액자"·"이름 바꾸기")가 있어,
      선택된 액자를 기준으로 "실시간 공유 링크 만들기"·"링크변경 반영"·PIN·폐기가 동작한다.
      자세한 구조는 "A-2. 세션당 액자 목록 관리" 참고.
    - **wepic 관리자 → 화면관리**에서도 액자(공유 폴더)별로 두 가지로 열 수 있다:
      **"wepic 메인화면 열기"**(`/?frame=<id>` — 그 액자를 관리자 자신의 세션에 편입시켜
      "현재 액자"로 선택하고, 저장된 사진·제목·전환설정을 그대로 불러온 뒤 이어서 **완전히
      편집**할 수 있다: 사진 추가(내 계정으로 다시 고르기)·제외, PIN 확인·변경, 제목·전환
      설정 변경, "링크변경 반영"까지 전부 이 화면에서 동작한다)와
      **"wepic 공유화면 열기"**(`/f/<id>` — 가족이 보는 화면).
      편입 상태에서는 좌상단에 빨간 **"관리자 모드 — 제목"** 배지가 떠서 남의 액자를 관리
      중임을 알려준다. 권한은 서버가 액자별로 검사한다(관리자·소유자·해당 PIN 보유자만 통과;
      관리자가 아직 목록에 없는 액자를 열면 `POST /api/frames/:id/select`가 자동으로 자기
      액자 목록에 편입시킨다). 기존 사진 중 다시 올리지 않은 것은 재다운로드 없이 그대로
      유지된다(구글 base URL이 없어도 서버가 기존 파일을 그대로 들고 온다).
11. ✅ **사진 다운로드 기능** _(구현 완료 — 링크 방식으로 재구성)_ — 다운로드 아이콘을
    누르면 **현재 보고 있는 사진 1장**이 바로 저장된다. wepic 메인화면과 wepic 공유화면
    양쪽에 있어 링크를 받은 가족도 바로 저장 가능. 파일명은
    `wepic_001_20240501_1430.jpg`처럼 순번+촬영일시.
    - **전체(일괄) 다운로드는 제거**했다. 여러 파일을 연속 저장하면 브라우저가 다중
      다운로드를 막거나 모바일에서 불안정해, "한 장씩"으로 단순화하는 편이 안정적.
    - **저장 방식: blob → 실제 서버 URL(Content-Disposition)로 전환.**
      기존 방식(`fetch` → `blob:` URL → `<a download>`)은 **카카오톡 등 인앱
      브라우저(WebView)에서 저장이 실패**했다. 인앱 WebView는 다운로드를 안드로이드
      `DownloadManager`에 위임하는데, `blob:`은 그 페이지 메모리 안에만 존재해
      외부 프로세스가 다시 받아올 수 없기 때문("다운로드 중"만 뜨고 저장 안 됨).
      → 이제 `?dl=<파일명>`을 붙인 **실제 URL**을 그대로 열고, 서버가
      `Content-Disposition: attachment` 헤더를 붙여 저장을 강제한다
      (`/img`·`/shares/*`, Express·Worker 양쪽 동일).
    - **동영상은 저장 대상 아님** — 동영상이 재생 중이면 다운로드 아이콘이 비활성화된다.
    - 남은 한계: 인앱 브라우저가 다운로드 자체를 차단하도록 만들어진 경우(일부 앱)는
      이 방식으로도 불가 → 그때는 "다른 브라우저로 열기" 안내가 유일한 대안.
      (안드로이드는 `intent://`로 유도 가능하나 보장 안 됨, iOS는 사용자 수동 조작만 가능)
12. ✅ **공유 링크 실시간 변경 반영** _(구현 완료)_ — "실시간 공유 링크 만들기" 옆에
    **"링크변경 반영"** 버튼 추가. 사진을 추가/제외하거나 제목·배경음악·전환설정을 바꾼 뒤
    누르면 **같은 링크**의 내용이 최신 상태로 갱신된다(서버가 세션별 shareId를 재사용).
    wepic 공유화면은 매니페스트의 `updatedAt`을 **20초마다 폴링**해 변경을 감지하면
    사진 목록·제목·배경음악·전환효과/간격을 **자동으로 갈아끼운다**(보고 있던 사진이
    남아 있으면 그 자리를 유지). 예: 10장 공유 후 2장 제외 + 3장 추가 → 반영을 누르면
    시청자 화면도 11장·새 제목·새 음악으로 바뀜.
13. ✅ **wepic 공유화면 재생 컨트롤 분리** _(구현 완료)_ — 기존에는 음악 버튼만 있어
    사진 슬라이드를 멈출 수 없었다. **배경음악 소리 on/off(음표 아이콘)** 와
    **사진 슬라이드 멈춤/재개(⏸/▶ 아이콘)** 를 아이콘으로 구분해 별도 버튼으로 제공.
    슬라이드를 멈추면 변경 폴링이 돌아도 타이머가 되살아나지 않는다.
14. ✅ **검색엔진 크롤링 방지** _(구현 완료)_ — 공유 링크는 "링크를 아는 사람만" 보는
    비공개성 경로이므로 색인되면 안 된다. 3중으로 차단:
    `robots.txt`(`/f/`·`/shares/`·`/img`·`/video`·`/api/` Disallow) +
    응답 헤더 `X-Robots-Tag: noindex, nofollow`(`/f/*`·`/shares/*`, Express·Worker 양쪽) +
    `share.html`의 `<meta name="robots" content="noindex, nofollow">`.
    - 참고: 공유 id는 랜덤 9바이트라 추측 불가하고 외부에서 링크된 곳도 없어 자연
      노출 가능성은 낮았지만, 링크가 공개된 곳에 올라가는 경우를 대비한 안전장치.
15. ✅ **공유 링크 PIN 번호** _(구현 완료)_ — 4자리 PIN 발급·표시·수정, 공유화면 입력 게이트,
    서버 측 우회 차단(HMAC 열람 쿠키). 상세는 아래 "다음에 할 일 A" 참고.

### A. ✅ 공유 링크 PIN 번호 적용 (보안 — 완료)

링크가 유출·전달되어도 PIN을 모르면 볼 수 없게 했다. (크롤링 방지는 검색엔진만 막고,
사람 손을 타고 퍼지는 것은 막지 못하므로 별도 필요)

- **발급**: wepic 메인화면에서 공유 링크를 만들면 서버가 **4자리 랜덤 PIN**을 발급하고,
  공유 버튼 옆에 표시한다. 🎲 버튼으로 새 PIN을 만들고 **"링크변경 반영"**을 누르면 갱신된다.
- **입력**: wepic 공유화면은 재생 전에 PIN 입력 화면을 띄우고, 맞을 때까지 재생하지 않는다
  (사진 목록도 받지 않고 변경 폴링도 시작하지 않음).
- **우회 방지(중요)**: 화면에서만 검사하면 `/shares/<id>/photos.json` 주소를 직접 열어
  우회할 수 있다. 그래서 **PIN이 맞으면 서버가 HMAC 열람 쿠키(24시간)를 발급**하고,
  `photos.json`과 **사진 파일 자체**도 그 쿠키 없이는 401로 거부한다(Express·Worker 동일).
  쿠키에는 PIN 대신 HMAC 토큰만 담는다. 만든 본인과 관리자는 통과.
- **하위 호환**: PIN이 없는 기존 공유 링크는 그대로 열린다.
- 남은 것(선택): PIN 없이 열리는 기존 링크를 일괄 정리하거나, 실패 횟수 제한(brute-force 방어).
  4자리는 1만 가지라 자동 대입에 이론상 취약하므로, 공개 노출이 늘면 시도 제한을 붙이는 게 좋다.

### A-2. ✅ 세션당 액자 목록 관리 (다중 액자 완성) _(구현 완료)_

**문제였던 것**: 한 세션에 `shareId`가 하나뿐이라 액자를 새로 만들면 이전 액자를 더 이상
갱신할 수 없었다("링크변경 반영" 불가) — 옛 액자는 그 시점 내용으로 고정되고 TTL 뒤 사라짐.

**구현 내용**: 세션이 **액자 목록**을 갖도록 바꿨다(Express·Cloudflare Worker 동일).
1. `session.shareId`(단일) → **`session.frames = [{ id, name }]` + `session.currentFrameId`** 로 확장.
   옛 세션(`shareId`만 있던 세션)은 `ensureFrames()`가 "액자 1"로 자동 이전.
2. wepic 메인화면 공유 블록에 **액자 선택 UI** 추가(`<select>` + "새 액자"·"이름 바꾸기" 버튼).
   선택한 액자를 기준으로 "실시간 공유 링크 만들기"·"링크변경 반영"·PIN 표시·폐기가 동작.
3. 액자에 **이름 붙이기**(제목과 별개의 관리용 이름, 매니페스트에 `frameName`으로 저장).
   관리자 화면관리·PIN번호관리 목록에도 `[이름]`으로 표시.
4. 액자별 삭제(폐기) 시 목록에서도 완전히 제거(폴더까지 삭제), 남은 액자 중 하나로 자동 전환.
5. PIN 우회(본인 소유 확인)를 `session.frames` 배열 전체를 기준으로 하도록 확장 —
   여러 액자 중 어느 것을 봐도 만든 본인은 PIN 없이 통과.

**참고**: 서버 저장 구조는 이미 액자별로 독립적(`shares/<id>/photos.json`)이라 DB 없이
세션(Express: 파일, Worker: KV)에 목록만 들고 다니는 방식으로 구현했다.

**API**: `GET/POST /api/frames`, `PUT /api/frames/:id`(이름 변경),
`POST /api/frames/:id/select`, `DELETE /api/frames/:id`.

**남은 선택사항**: 한 계정이 만들 수 있는 액자 수 제한(현재 무제한, 저장공간·TTL 정책에 따라
추후 조정 가능).

### A-3. 🔶 OIDC 구현해서 회원관리하기 (구글 완료, 카카오·네이버·회원관리 화면 남음)

**지금 상태 (확인된 것)**
- 로그인은 구글 **OAuth 2.0 인가코드** 흐름만 쓴다. **`id_token`을 받지도, 검증하지도 않고**
  액세스 토큰으로 `/oauth2/v3/userinfo`를 호출해 이메일·이름을 얻는다.
- **서버에 회원(허용 사용자) 개념이 아예 없다.** 구글 로그인을 통과하면 누구나 사용 가능하고,
  실제 차단은 **Google Cloud Console의 "테스트 사용자" 목록**에만 의존한다(게시 상태가
  테스트일 때만 유효). "사용자 등록 신청" 메뉴는 관리자 이메일 안내문일 뿐 등록 절차가 없다.
- 사용자 식별을 **이메일**로 한다(관리자 판정도 `ADMIN_EMAILS` 이메일 비교).

**왜 OIDC로 바꾸는가**
- **`id_token`(JWT) 검증**: 구글 JWKS로 서명·`iss`·`aud`·`exp`·`nonce`를 검증하면 신원을
  네트워크 추가 호출 없이 확인할 수 있고, 토큰 위조·재사용을 막는 표준 방식이 된다.
- **안정적 사용자 키 `sub`**: 이메일은 변경·재사용될 수 있어 회원 식별 키로 부적절하다.
  OIDC의 `sub`(구글 계정 고유 ID)를 회원 키로 쓰면 이메일이 바뀌어도 동일 회원으로 유지된다.
- **확장성**: 애플·카카오·네이버 등도 OIDC 계열이라, 나중에 로그인 수단을 늘릴 때 구조를 재사용할 수 있다.
- **구글 심사 의존 탈피**: 우리 서버가 회원을 관리하면 "테스트 사용자 20명" 같은 제약과
  분리해 초대·승인제를 운영할 수 있다.

**구현 상태 (2026-07)** — 🔶 구글 완료, 카카오·네이버 대기

| 항목 | 상태 |
|---|---|
| Google OIDC (id_token + JWKS 검증) | ✅ 완료 — 프로덕션에서 실제 로그인 왕복 검증 |
| D1 회원 저장 + 자동 승인 | ✅ 완료 |
| 관리자 판정을 `role='admin'`으로 전환 | ✅ 완료 |
| 상단 메뉴에 3개 제공자 로그인 버튼 | ✅ 완료 (카카오·네이버는 "준비중" 비활성) |
| 카카오 OIDC | 🔶 서버 구조 완료, **앱 키 입력 대기** |
| 네이버 로그인 | ⬜ 미착수 (정식 OIDC 아님 — 아래 참고) |
| 회원관리 화면(목록·차단) | ⬜ 미착수 |
| 사진 업로드 로그인 강제 + 3단계 권한 적용 | ✅ 완료 (아래 **A-4** 참고) |

**결정된 정책**
- **신규 가입은 자동 승인**(`status='active'`) — 승인 대기(pending) 없음. 공개 서비스 지향.
- **관리자는 DB에서 직접 지정**한다. `ADMIN_EMAILS` 환경변수 기반 자동 부여는 **쓰지 않는다**
  (환경변수 없이 DB가 유일한 진상이 되도록). 지정 방법:
  ```bash
  npx wrangler d1 execute wepic-db --remote \
    --command "UPDATE users SET role='admin' WHERE email='garzette@gmail.com';"
  ```
  ⚠️ 회원 행은 **첫 로그인 때 생성**되므로, 로그인 전에 이 명령을 실행하면 `changes: 0`이 된다.
- **구글만 사진 접근 권한까지 함께 받는다.** 카카오·네이버로 가입한 회원은 구글 포토 Picker를
  쓸 수 없어 "기기 갤러리에서 직접 올리기"(J 항목)를 사용한다. `/api/status`의
  `canPickGooglePhotos`로 화면이 이를 구분한다.

**구현 내용 (`cloudflare/index.js`)**
1. **`OIDC_PROVIDERS` 레지스트리** — 제공자별 authUrl·tokenUrl·jwksUrl·issuers·scope를 한 곳에
   모아, 새 제공자는 항목 추가만으로 붙는다. 구글은 기존 `/auth/callback` 주소를 유지하고
   그 외는 `/auth/<provider>/callback`을 쓴다(구글 콘솔 재설정 불필요).
2. **`verifyIdToken()`** — JWKS로 RS256 서명을 검증하고 `iss`·`aud`·`exp`·`nonce`까지 확인.
   `/oauth2/v3/userinfo` 호출을 없애 네트워크 왕복을 줄였다.
3. **state·nonce** — 로그인 시작 때 만들어 KV에 10분간 보관하고, **state는 1회용**(CSRF·재사용 차단).
4. **`upsertUser()`** — `(provider, provider_sub)`가 회원 식별 키(이메일은 변경 가능하므로 키로
   쓰지 않음). 이메일 미동의로 NULL이 와도 `COALESCE`로 기존 값을 보존한다.
5. **권한 재확인** — `requireAdmin`은 세션 캐시가 아니라 **매 요청 D1을 다시 읽는다.**
   관리자를 DB에서 내리면 재로그인 없이 즉시 막힌다.
6. **`requireMember()`** 가드 추가 — "회원이면 되는" 엔드포인트용(업로드 로그인 강제에 사용 예정).
7. **차단 회원**(`status='blocked'`)은 로그인·API 모두 거부.
8. **`availableProviders`** — `/api/status`가 "키가 실제로 설정된 제공자"만 알려주어, 미설정
   제공자 버튼을 눌러 오류를 보는 일이 없다.

**남은 결정**
- 회원 데이터 보관·삭제 정책(탈퇴 시 세션·공유 링크 처리) — 아직 탈퇴 기능 없음.
- **네이버**: 정식 OIDC(id_token/JWKS)가 아니라 구형 OAuth 2.0 + 프로필 조회 방식으로 알고 있다.
  구현 전에 네이버 개발자센터 최신 문서로 확인이 필요하다(확신 없음).

**저장소**: 회원은 **D1**(`wepic-db`, APAC 리전)에 둔다. 스키마는 저장소 루트 `schema.sql`.
접근 패턴이 단순한 키 조회라 KV로도 가능했지만, 회원 목록·검색·통계를 감안해 SQL을 택했다.

**회원관리 화면(미착수)**: wepic 관리자에 "회원관리" 메뉴 추가 — 회원 목록(제공자·가입일·최근
로그인·역할·상태), **차단/차단해제**, 역할 변경(user ↔ admin). `requireAdmin`이 이미 D1을 매번
읽으므로, 여기서 `status='blocked'`로 바꾸면 해당 회원은 다음 요청부터 즉시 막힌다(재로그인
불필요 — 이미 로그인된 세션도 API 호출 시 다시 검사되기 때문). API는 D1 `users` 테이블을
직접 조회/갱신하면 되고 새 저장 구조는 필요 없다.

### A-4. ✅ 사진 업로드 로그인 강제 + 3단계 권한 적용 (완료, 2026-07)

**문제였던 것**: OIDC(A-3)로 회원 식별은 됐지만, 어떤 엔드포인트도 "Wepic 회원인가"를
검사하지 않았다. `/api/share`는 `requireLogin`(구글 access token 필요)을 쓰지만 이건 "구글
사진 API를 쓸 수 있는가"를 검사하는 것이지 회원 여부 검사가 아니다. `/api/share/blob`
(게스트 업로드 경로)·액자 생성/이름변경/선택/선택해제/삭제는 로그인 검사 자체가 없었다.

**구현 내용** (`cloudflare/index.js`)
1. 아래 쓰기 전용 라우트에 **`requireMember()`** 가드를 적용했다(비회원·차단 회원은
   즉시 401, DB/KV/R2에 아무것도 쓰지 않고 중단):
   - `POST /api/share/blob` (구글 포토 "공유"로 받은 사진 업로드 — 예전엔 게스트도 가능했으나
     이제 로그인 필요)
   - `DELETE /api/share` (공유 링크 폐기)
   - `POST /api/frames`, `PUT /api/frames/:id`, `POST /api/frames/:id/select`,
     `POST /api/frames/deselect`, `DELETE /api/frames/:id` (액자 생성·이름변경·선택·선택해제·삭제)
   - `GET /api/frames`(조회)는 그대로 열어둠 — 읽기 전용이라 문제 없음.
2. 가드 통과 후 핸들러들은 `getSession()`을 다시 부르지 않고 `requireMember`가 넘겨준
   `sess`를 그대로 쓰도록 리팩터링했다(게스트용 "세션 즉석 발급" 분기 제거 — 로그인 세션은
   항상 존재가 보장되므로).
3. **프론트엔드**(`app.js`): 공용 `api()` 헬퍼가 이미 401을 `selectPanel('login')`으로
   처리하고 있어 별도 배선 없이 그대로 재사용된다. 다만 `init()`이 홈 진입마다 무조건 호출하는
   `POST /api/frames/deselect`(방문할 때마다 "새 액자"로 초기화하는 하우스키핑)까지 `api()`를
   쓰면, 게스트가 홈만 열어도 401→로그인 패널로 튕기는 회귀가 생겨 이 호출만 `api()` 대신
   일반 `fetch()`로 바꿔 결과를 조용히 무시하도록 했다. 그 외 사용자가 직접 누르는 액자·공유
   버튼들은 그대로 `api()`를 써 401을 로그인 화면 이동으로 처리한다.
   또한 PWA 공유 타깃(`isSharedMode`) 진입 시에도 실제 로그인 여부(`/api/status`)를 먼저
   확인해 `guest` 판정에 반영했다 — 이전에는 이 경로로 들어오면 실제 로그인 회원이어도 항상
   게스트로 취급돼 공유 블록 UI가 숨겨질 뻔했다.
4. **3단계 권한 최종 점검**:
   - **Wepic 관리자**(`role='admin'`) — wepic 관리자 화면 전체 접근. `requireAdmin`으로 적용됨.
   - **Wepic 사용자**(로그인 회원) — wepic 메인화면에서 사진 선택·공유 링크 생성.
     `requireMember()`을 업로드·액자 관리 경로에 적용 완료.
   - **Wepic 조회자**(비로그인) — wepic 공유화면(`/f/<id>`)만 조회. 로그인 없이 동작하며
     PIN 게이트(A 항목)로 보호됨 — 변경 없음(의도된 공개 기능).

**참고**: 데모 모드(`/demo/*`)는 위 3단계와 무관하게 항상 로그인 없이 열린다(설계상 별도 분리).
(무료 티어: 5GB · 하루 읽기 500만 행 / 쓰기 10만 행)

### B-2. ✅ My사진관리 (Wepic 사용자용, 완료 2026-07)

일반 **Wepic 사용자**(로그인한 회원, 관리자 아님)를 위한 화면. 상단 메뉴의 **"사진 선택"과
"데모로 보기" 사이**에 "📂 My사진관리"가 있고(로그인했을 때만 노출), 누르면 관리자와 동일한
구조로 좌측에 **화면관리·PIN번호관리** 하위 메뉴가 펼쳐진다. 다만 **본인이 만든 액자만** 보인다.

- **소유 판별은 고유값(D1 회원 id)으로 한다 — 이름이나 이메일이 아니다.** 매니페스트에
  `ownerUserId`(로그인 시 세션에 있는 D1 `users.id`)를 함께 저장해두고, 목록 조회 시
  `ownerUserId`가 본인과 일치하는 것만 걸러낸다. 이메일이 없는 카카오 회원도, 나중에
  이메일이 바뀐 회원도 정확히 자기 것만 보인다.
- 화면관리·PIN번호관리는 **관리자 화면과 똑같은 렌더링 함수를 공유**한다
  (`app.js`의 `loadShareList`/`shareRow`가 `scope`(`'admin'` | `'my'`)만 다르게 받아
  API 엔드포인트를 바꾼다). 서버도 `listShares(env, filterFn)`를 공유하고
  `adminShares`는 전체, `myShares`는 `ownerUserId` 필터만 다르다.
- **"wepic 메인화면 열기"** (사진 추가/제외·PIN·설정 편집)도 관리자와 동일하게 된다 —
  `POST /api/frames/:id/select`의 자동 편입 로직을 "관리자거나, 본인 소유(`ownerUserId`
  일치)면" 허용하도록 넓혔다. 그래서 다른 기기에서 만든 내 액자도 이어서 편집할 수 있다.
- **PIN 수정·삭제는 소유자 확인 후에만** 허용(`mySetPin`/`myDeleteShare`가 403으로 막음).
- **한계**: 이 기능 배포 **이전에** 만들어진 액자는 `ownerUserId`가 없어 My사진관리에는
  안 보인다(관리자 화면관리·직접 링크로는 그대로 보임). "링크변경 반영"으로 한 번 더
  저장하면 그때부터 `ownerUserId`가 채워져 My사진관리에도 나타난다.

**검증**: 로컬 D1/R2/KV에 서로 다른 소유자의 액자 2개를 만들어, 목록 필터링·PIN 수정(본인 성공/
타인 403)·삭제(본인 성공/타인 403)·프레임 자동편입(본인 성공/타인 404)을 모두 API로 확인했고,
브라우저에서 메뉴 노출·좌측 하위 메뉴 전환·목록 렌더링·PIN 저장까지 실제 클릭으로 재현했다.

### F. ✅ 지워지지 않는 저장소 (자동 만료 비활성화) _(구현 완료, 2026-07)_

기존엔 공유 링크가 `SHARE_TTL_HOURS`(기본 24시간) 뒤 앱이 직접 자동 삭제했다
(`cleanupExpiredShares`/`cleanupExpired`, 매시간 실행 + `/f/:id` 접근 시 즉시 확인). **이건
Cloudflare가 하는 게 아니라 Wepic 애플리케이션 코드가 스스로 지우던 것**이었다 — 무료 R2 용량이
넉넉하므로, 따로 얘기하기 전까지 어떤 공유도 자동으로 지우지 않도록 바꿨다.

**구현 내용**(Express·Cloudflare Worker 동일):
- `writeShareManifest`/`writeManifest`: 더 이상 `expiresAt`을 계산해서 채우지 않는다(`null`로 저장).
- `isShareExpired`/`isExpired`: 시간 비교 로직을 없애고 항상 `false`를 반환하도록 바꿨다
  (Worker 쪽은 매니페스트 파싱 실패 같은 손상 데이터 방어를 위해 `!m`만 유지).
  **이미 만들어져 있던 공유(과거 코드가 찍어둔 실제 `expiresAt` 값 포함)도 이 값 자체를
  더 이상 보지 않으므로 함께 보존된다** — 기존 자료를 개별로 손댈 필요가 없었다.
- 매시간 정리 크론/인터벌 호출은 멈췄다(Worker는 `scheduled` 핸들러를 빈 함수로,
  Express는 `cleanupExpiredShares()` 호출 자체를 제거). 크론 트리거 등록은 남아 있어도 무해하다.
- `SHARE_TTL_HOURS` 환경변수는 더 이상 읽지 않는다(`wrangler.toml`·`.env.example`·`web/README.md`에서
  관련 문구 정리).

**되살리려면**: `writeShareManifest`/`writeManifest`에 만료시각 계산을 복원하고,
`isShareExpired`/`isExpired`를 실제 시간 비교로 되돌리면 된다(각 함수 옆에 주석으로 남겨둠).

**참고**: 아래 **H(사업모델)** 은 "영구 보관"이 아니라 그 위에 얹는 **유료 재열람/복원** 아이디어라
별개 논의다 — 지금은 무료로 전부 영구 보관되는 상태이고, H는 나중에 정책을 바꿀 때(예: 무료는
다시 TTL, 유료는 영구)를 위한 사업모델 메모다.

### I. ⬜ PWA 앱을 쉽게 설치·배포할 수 있게 하기 (다음 우선순위)

**문제**: 지금은 사용자가 URL을 알아야 하고, 브라우저 메뉴에서 "홈 화면에 추가"를 **직접**
찾아 눌러야 설치된다. 안드로이드 크롬은 조건을 만족하면 자동으로 "설치" 배너를 띄워주기도
하지만, **iOS 사파리는 완전히 수동**이다(공유 버튼 → "홈 화면에 추가"가 숨겨져 있어 인지도가
낮음). 지금 코드는 `beforeinstallprompt` 이벤트(Android/Chrome이 설치 가능 여부를 알려주는
이벤트)를 아예 듣고 있지 않아, 설치 유도 자체를 하지 않고 있다.

**해결 방향**
1. **설치 안내 UI**: 기기 감지(iOS vs Android/기타)로 맞춤 안내를 보여준다.
   - Android/Chrome: `beforeinstallprompt` 이벤트를 잡아 저장해뒀다가, "앱 설치" 버튼을 눌렀을
     때 그 이벤트의 `prompt()`를 호출 — 지금은 이 리스너 자체가 없다(`app.js`에 추가 필요).
   - iOS: 이 이벤트가 없으므로 User-Agent로 iOS를 감지해 "공유 버튼 → 홈 화면에 추가" 안내를
     스크린샷과 함께 보여주는 수동 가이드가 필요하다.
2. **QR 코드로 설치 유도**: 가족에게 wepic 링크를 알려줄 때 설치 안내 페이지 QR도 같이
   주면, 앱을 몰라도 스캔 한 번으로 설치 화면까지 이동 가능(QR 생성은 이미 `web/public/vendor/qr.js`에
   구현돼 있어 재사용 가능).
3. **(장기, 별도 조사 필요) 네이티브 앱스토어 등록**: TWA(Trusted Web Activity, Android)나
   PWABuilder로 Google Play·iOS App Store에 최소 래퍼로 올리는 방법. 신뢰도는 오르지만
   심사·유지보수 부담이 늘어나므로 반응을 본 뒤 검토.

> ⚠️ 아래 3번의 "네이버는 OIDC가 아니다"는 **옛 정보**다. 네이버도 OpenID Connect를
> 지원해 구글과 같은 틀(id_token + JWKS 검증)로 구현했다. 서명이 **ES256**이라 검증기에
> 알고리즘 표를 만들어 함께 지원하고, 토큰 교환에 `state`를 넘긴다.
> **페이스북도 같은 방식으로 함께 추가**했다. 남은 것은 각 콘솔 등록 + 시크릿 넣기뿐이다.

지금 로그인 제공자는 **구글·카카오 2개**다. 코드에는 네이버 자리(`OIDC_PROVIDERS.naver`)가
이미 잡혀 있고 화면에도 "네이버로 계속하기 (준비중)"로 비활성 표시된다 — 서버가
`/api/status`의 `availableProviders`로 "키가 설정된 제공자"만 알려주므로, **키를 넣는 순간
버튼이 살아난다.**

**해야 할 일**
1. [네이버 개발자센터](https://developers.naver.com)에서 애플리케이션 등록 →
   `Client ID` / `Client Secret` 발급. 서비스 URL과 **Callback URL**에
   `https://<BASE_URL>/auth/naver/callback`을 등록한다.
2. `wrangler secret put NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` (로컬은 `.dev.vars`).
3. `cloudflare/index.js`의 `OIDC_PROVIDERS.naver` 구현 확인·보완.
   ⚠️ **네이버는 OIDC가 아니라 OAuth 2.0이다** — 구글처럼 `id_token`을 주지 않으므로
   access_token으로 `https://openapi.naver.com/v1/nid/me`를 호출해 사용자 정보를 받아야 한다
   (구글은 id_token+JWKS 검증, 카카오는 별도 처리 — 세 번째 패턴이 하나 더 생긴다).
4. `grantsPhotos: false` — 네이버 계정은 구글 포토를 쓸 수 없으므로 **기기 갤러리 업로드**
   경로로 간다(`canUseGooglePhotos()`가 이미 그렇게 갈라준다).
5. 회원 식별은 `users(provider='naver', provider_sub=<네이버 고유 id>)` — 표 변경은 필요 없다.

### N. ✅ 자체 도메인 연결 (완료, 2026-08-08 — **wepic.kr**로 진행. E · J-16 ⑨ 참고)

> 아래는 계획 당시 메모다. 실제로는 `wepic-live.com`이 아니라 **`wepic.kr`**로 연결했고,
> 3번(`BASE_URL` 교체) 대신 **요청 주소 기준으로 조립**하는 방식을 택해 두 주소가 함께 산다.

지금 주소는 `https://wepic-live.wepiclab.workers.dev`(호스트만 31자)다. 짧은 주소
(`/w/<6자>`, J-14)를 넣었어도 **길이의 대부분이 호스트**라 체감이 크지 않다.

**해야 할 일**

2. `wrangler.toml`에 커스텀 도메인 라우트 추가:

   custom_domain = true

   (`www`도 쓸 거면 같은 방식으로 하나 더 두고 한쪽을 리다이렉트한다)
3. **`[vars] BASE_URL`을 새 도메인으로 바꾼다.** 이 값이 공유 링크·짧은 주소·OAuth

4. **로그인 제공자 3곳의 Redirect URI를 모두 추가**한다(빼지 말고 **추가** — 이전 주소로
   들어오는 링크가 남아 있다):
   - 구글: Cloud Console > 사용자 인증 정보 > 승인된 리디렉션 URI
   - 카카오: 내 애플리케이션 > 카카오 로그인 > Redirect URI

6. ⚠️ **이미 저장된 wepic의 주소는 자동으로 바뀌지 않는다** — 매니페스트에는 상대 경로만
   들어 있고 링크는 `BASE_URL`로 매번 조립하므로, 3번만 바꾸면 목록·공유 화면에 나오는

### O. ⬜ 구글 로그인 "확인되지 않은 앱" 경고 없애기 (앱 게시 + 확인 심사)

지금 구글 로그인을 누르면 **"Google에서 확인하지 않은 앱입니다"** 경고가 뜨고, 사용자가
"고급 → 안전하지 않음(이동)"을 눌러야 넘어간다. 개발자만 쓰는 화면이면 상관없지만
**남에게 링크를 나눠주는 서비스에서는 이 화면 하나로 대부분 이탈한다.**

**원인** — 우리가 요구하는 `photospicker.mediaitems.readonly`는 구글이 **민감한 범위
(sensitive scope)**로 분류하는 권한이다. 민감한 범위를 쓰는 앱은
① OAuth 동의 화면이 **테스트(Testing)** 상태이거나 ② **게시(In production)** 상태라도
**확인(verification) 심사를 통과하지 않았으면** 이 경고가 계속 나온다. 즉 게시 상태로
바꾸는 것만으로는 없어지지 않는다 — **심사 통과까지 가야 한다.**

> 참고: 테스트 상태에는 다른 부작용도 있다. **테스트 사용자 100명 제한**이 있고,
> 발급된 **리프레시 토큰이 7일 만에 만료**되어 주기적으로 다시 로그인해야 한다.

**해야 할 일 (Google Cloud Console → API 및 서비스 → OAuth 동의 화면)**

1. **앱 정보를 실제 운영 도메인으로 맞춘다** — 앱 이름 `Wepic`, 지원 이메일, 로고(120×120 이상),
   앱 홈페이지 `https://wepic.kr`. 로고는 심사 대상이라 **아이콘과 서비스명이 일치**해야 한다.
2. **승인된 도메인에 `wepic.kr` 등록** + **Google Search Console에서 도메인 소유권 확인.**
   ⚠️ 소유권 확인은 **Cloud 프로젝트 소유 계정과 같은 구글 계정**으로 해야 인정된다.
3. ⬜ **개인정보처리방침·이용약관 페이지를 URL로 만든다** (`https://wepic.kr/privacy`,
   `https://wepic.kr/terms`). 지금은 회원가입 팝업 안에 글로만 있어 **주소가 없다** —
   심사에는 반드시 공개된 URL이 필요하다. **이 항목이 실제 개발이 필요한 유일한 작업이다.**
   내용에는 "무엇을(구글 포토에서 고른 사진) · 왜 · 어디에(Cloudflare R2) 저장하고
   어떻게 지우는지"와 회원탈퇴 방법을 적는다.
4. **범위(Scope)에 `photospicker.mediaitems.readonly`를 선언하고 사용 이유를 적는다** —
   "사용자가 직접 고른 사진만 받아 액자·공유 링크를 만든다. 라이브러리 전체는 읽지 않는다"가
   핵심 논리다(Picker API는 사용자가 고른 것만 준다는 점이 심사에 유리하다).
5. **데모 영상을 유튜브에 올린다(미등록/일부공개 가능).** 반드시 담아야 하는 장면:
   OAuth 동의 화면 주소창(client_id가 보이게) → 동의 → 사진 선택 → 그 사진이 화면에서
   어떻게 쓰이는지. **영상이 없거나 동의 화면이 안 나오면 거의 반려된다.**
6. **게시 상태를 "프로덕션"으로 바꾸고 확인 심사를 제출한다.** 보통 며칠~몇 주 걸리고
   보완 요청 메일이 오간다. 심사 중에도 서비스는 계속 동작한다(경고만 남는다).

**심사 전까지의 임시 대응**: 테스트 사용자 목록에 쓸 사람의 계정을 넣으면 그 사람은
경고 없이 쓸 수 있다(100명 한도). 카카오·네이버·페이스북 로그인은 이 경고와 무관하므로,
심사가 끝날 때까지는 **구글 외 로그인 안내를 앞세우는 것도 방법이다.**

- [민감한 범위 확인 심사](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification)
- [확인되지 않은 앱 경고 안내](https://support.google.com/cloud/answer/7454865)
- [OAuth 앱 확인 도움말](https://support.google.com/cloud/answer/13463073)

### K. ⬜ 인스타그램 자동 포스팅 (다음 구현 예정)

만든 wepic 컨텐츠를 인스타그램에 **자동으로 올리는** 기능. 사용자가 "인스타그램에 올리기"를

**알아둘 제약** (구현 전에 확인 필요)
- 인스타그램 개인 계정에는 게시 API가 없다. **Instagram Graph API의 Content Publishing**을

  ② `POST /{ig-user-id}/media_publish`로 게시한다. 캐러셀은 컨테이너를 여러 개 만들어 묶는다.

**구현 방향(초안)**: 회원정보 화면에 "인스타그램 연결"을 두고 Facebook OAuth로 페이지·IG
계정을 고르게 한 뒤 토큰을 D1에 저장 → wepic 화면에 "인스타그램에 올리기" 버튼 →
Worker가 위 2단계를 호출. 이미지 URL은 전체공유 wepic의 `/shares/<id>/photos/*`를 그대로 쓸
수 있다(PIN이 걸린 wepic은 인스타가 접근할 수 없으므로 전체공유만 지원하거나 임시 공개 URL 발급).

### J-2. ✅ 사진 촬영일시를 EXIF에서 읽기 (업로드 날짜가 보이던 버그 수정, 2026-07)

기기에서 올린 사진의 날짜가 **촬영일이 아니라 올린 날짜/시간**으로 보이는 문제가 있었다.
원인은 파일의 `lastModified`를 촬영시각으로 썼기 때문이다 — 갤러리에서 공유하거나 다운로드받은
사진은 이 값이 "기기에 복사된 시각"이라 오늘 날짜가 되어버린다.

- `readExifDateTime(blob)`을 직접 구현했다(외부 라이브러리를 쓸 수 없는 환경). JPEG 세그먼트를
  훑어 **APP1(Exif) → TIFF 헤더 → IFD0 → ExifIFD → DateTimeOriginal(0x9003)** 을 읽고,
  없으면 `DateTimeDigitized(0x9004)` → `DateTime(0x0132)` 순으로 대체한다.
  파일 앞 256KB만 읽어 큰 사진도 부담이 없다.
- `bestPhotoTime()`이 **EXIF → lastModified → 현재시각** 순으로 결정한다.
  PWA 공유 유입(`loadSharedMedia`)과 갤러리 직접 업로드 양쪽에서 이걸 쓴다.
- 동영상은 EXIF가 없어 기존대로 파일 시각을 쓴다.
- **검증**: DateTimeOriginal=`2019:08:15 07:45:30`을 담은 최소 JPEG를 만들어 브라우저에서
  파싱시켰고, `lastModified`를 "오늘"로 줬는데도 2019년이 나오는 것을 확인했다(EXIF 우선).
  EXIF 없는 파일은 오늘로 정상 대체됨.

### J-3. ✅ 공유화면 이전/다음 사진 버튼 + 공유 버튼 하나로 통합 (완료, 2026-08-01)

**(1) wepic 공유화면 — 이전(‹)·다음(›) 버튼 추가 + 아이콘 존재감 낮추기**

- `share.html`의 하단 아이콘 줄(`.share-actions`)에 멈춤/재개 버튼을 가운데 두고
  **‹ 이전 사진 / › 다음 사진**을 양옆에 배치했다(미디어 플레이어와 같은 순서).
- `step(delta)`를 새로 만들었다. 자동 전환 타이머를 **끊고 다시 걸어서**, 방금 손으로 넘긴
  사진이 곧바로 지나가지 않게 한다. 끝에서 넘기면 처음으로(양방향 순환).
  멈춤 상태에서 누르면 **멈춘 채로 한 장만** 이동한다(`resetTimer()`가 멈춤이면 그냥 빠진다).
- 아이콘이 사진을 방해하지 않도록 **작고 희미하게** 다시 손봤다.
  버튼 `44px → 30px`, 아이콘 `18px → 14px`, 배경 `rgba(0,0,0,0.26)`,
  색은 `rgba(238,238,238,0.68)` — 우측 하단 날짜·곡목 캡션(`rgba(200,200,200,0.55)`)보다
  **조금 더 흰색**이라 "누를 수 있는 것"으로는 보이되 튀지는 않는다.
- **검증**: 로컬 R2에 사진 3장짜리 임시 공유를 만들어 실제로 눌러봤다. 이전/다음이
  양방향 순환까지 정상 동작하고 캡션·진행바가 함께 갱신됐으며, 멈춘 상태에서 눌러도
  멈춤이 풀리지 않았다. 계산된 스타일로 크기·색상도 확인했고 콘솔 오류는 없었다.
  (확인 후 임시 공유는 삭제)

**(2) wepic 메인화면 공유 블록 — 버튼 하나만 보이게**

액자가 만들어진 뒤에도 "실시간 공유 링크 만들기"와 "링크변경 반영"이 **둘 다 보여서**
어느 쪽을 눌러야 하는지 헷갈렸다.

- `setShareLinkState(hasLink)` 한 곳에서 상태를 정한다. 링크가 없으면 **"실시간 공유 링크
  만들기"만**, 링크가 있으면 **"링크변경 반영"만** 보인다. 항상 버튼은 하나다.
- 액자 이름 리스트박스 옆에 아이콘 **2개를 추가**했다(기존 `+` 새 액자 · `✎` 이름 바꾸기 뒤에):
  **📋 주소 복사하기**, **🗑 링크 삭제하기**. 링크가 있는 액자에서만 나타난다.
- "링크변경 반영"은 원래부터 **사진 추가·삭제, 제목, 배경음악, 전환 간격·효과, PIN을 한 번에**
  저장한다(`pushShare('update')`가 전부 같이 보낸다). 따로 저장할 것이 없다는 걸 알 수 있게
  버튼 설명과 완료 토스트 문구를 그렇게 고쳤다.
- 삭제 로직은 `revokeCurrentShare(btn)`으로 묶어 안내 팝업의 버튼과 🗑 아이콘이 함께 쓴다.
  용어도 "폐기" → **"삭제"**로 통일했다.
- **검증**: 홈에서 세 가지 상태(초기·링크 있음·링크 없음)를 만들어 보이는 버튼이
  **항상 정확히 하나**이고, 두 아이콘이 링크 있을 때만 나타나는 것을 확인했다.

### J-4. ✅ 화면 자동 꺼짐 방지 + 세로 사진 블러 배경 (완료, 2026-08-01)

액자 가전제품처럼 보이게 하는 두 가지. **wepic 메인화면과 공유화면 양쪽에 모두** 적용했다.

**① Screen Wake Lock — 화면 자동 꺼짐 방지**

태블릿·PC를 액자로 세워두면 절전 설정 때문에 몇 분 뒤 화면이 꺼져 버린다.

- `navigator.wakeLock.request('screen')`으로 사진을 보는 동안 화면을 깨워 둔다.
- 잡는 시점: 메인화면은 `showSlideshow()`(슬라이드쇼 진입), 공유화면은 `applyManifest()`에서
  **볼 사진이 실제로 있을 때**(= PIN 게이트를 통과한 뒤).
  놓는 시점: 메인화면에서 `showHome()`·`showPicker()`로 나갈 때. 사진을 보지 않는 화면에서
  절전을 막아둘 이유가 없다.
- **탭을 벗어나면 브라우저가 잠금을 자동 해제**한다. 그래서 `release` 이벤트에서 참조를 비우고,
  `visibilitychange`로 돌아왔을 때 다시 잡는다. 이게 없으면 다른 앱 한 번 갔다 오면
  그 뒤로 영원히 화면이 꺼진다.
- 미지원 브라우저(iOS 사파리 등)나 사용자가 막은 경우에는 `catch`로 조용히 넘어가고
  기능만 없이 정상 동작한다. **iOS는 이 API가 없어 효과가 없다** — 아이패드를 액자로 쓸 때는
  기기 설정에서 자동 잠금을 "없음"으로 바꿔야 한다.
- **검증**: 미리보기 창은 `visibilityState`가 항상 `hidden`이라 실제 잠금을 못 잡는다
  (`NotAllowedError: The requesting page is not visible` — 브라우저 규칙대로 동작).
  그래서 API를 가짜로 바꿔 상태 흐름을 확인했다: 획득 → 브라우저 자동 해제 → 복귀 시 재획득
  → 나갈 때 해제까지 순서대로 정확히 동작했고, 중복 호출·해제 후 재요청은 무시됐다.
  Demo 재생으로 진입 시 실제로 요청이 걸리고 홈으로 나가면 풀리는 것도 확인했다.

**② 세로 사진 배경 가우시안 블러**

세로 사진은 `object-fit: contain` 때문에 양옆이 검은 여백으로 남아 액자 느낌이 떨어졌다.

- 사진 레이어(`#photo-a`/`#photo-b`) 뒤에 **같은 사진을 `object-fit: cover`로 꽉 채운 배경
  레이어**(`#photo-a-bg`/`#photo-b-bg`)를 깔았다.
  `filter: blur(26px) brightness(0.5) saturate(1.15)` — 사진 자체가 계속 주인공이도록 어둡게 눌렀다.
- `transform: scale(1.14)` — `blur`는 요소 경계에서 잘려 테두리가 비어 보이므로 살짝 확대해
  경계를 화면 밖으로 밀어낸다.
- 쌓임 순서는 **z-index를 쓰지 않고 DOM 순서로** 잡았다(배경 `<img>`를 사진보다 먼저 둠).
  z-index를 주면 제목·시계 같은 오버레이보다 위로 올라와 덮어버린다.
- **여백이 생길 때만** 켠다: 사진 화면비가 화면과 **5% 이상** 다를 때(`needsBackdrop()`).
  화면을 꽉 채우는 사진에 쓸데없이 blur 연산을 하지 않는다. 세로 사진뿐 아니라
  **가로로 아주 긴 사진(위아래 여백)** 에도 같이 적용된다.
- 크로스페이드는 사진 레이어와 배경 레이어가 같은 `transition`으로 함께 넘어간다.
  동영상 항목은 원본 그대로 재생하므로 배경을 끈다.
- **전체화면 전환·창 크기 변경**으로 화면비가 바뀌면 여백 여부도 달라진다 →
  `resize`·`fullscreenchange`에서 `refreshBackdrop()`으로 현재 사진만 다시 판단한다.
- **검증**: 로컬 R2에 세로 900×1200 / 가로 1920×1080 / 세로 720×1280 사진으로 임시 공유를
  만들어 넘겨봤다. 배경 레이어가 사진 레이어와 정확히 같은 src로 함께 켜지고 꺼졌으며,
  계산된 스타일로 `cover`·blur·scale을 확인했다. 임계값은 화면비와 같은 사진·+3%는 꺼지고
  +10%·세로 3:4는 켜지는 것을, DOM 순서는 `배경 → 사진 → 제목` 순인 것을 확인했다.
  메인화면은 Demo(1920×786, 아주 넓은 사진)로 배경이 켜지는 것을 확인했다.

**아직 안 한 것 — 듀얼 액자 모드(세로 사진 2장 나란히)**

요청에서 블러 배경과 **"또는"**으로 제시된 대안이라 우선 블러 배경만 넣었다. 블러 배경은
세로 사진이 1장만 있어도 항상 통하지만, 듀얼 모드는 세로 사진이 연속으로 올 때만 성립한다.
넣으려면 다음이 함께 바뀌어야 해서 별도 작업으로 남긴다:
전환 시 **2장씩 넘어가는 인덱스 처리**, 캡션에 **어느 쪽 날짜를 쓸지**, 사진 저장 버튼이
**어느 장을 내려받을지**, 진행바 계산, 동영상이 섞였을 때의 처리, 그리고 켜고 끄는 설정
(매니페스트에 저장 → 공유화면까지 전달).

### J-5. ✅ 홈페이지 디자인 재개편 — 상단 바 + 시네마틱 배경 (완료, 2026-08-01)

참고: `awwwards.com/sites/tom-carder-media` (실제 사이트 `tomcardermedia.com`).
참고 사이트의 구성은 **왼쪽에 텍스트 워드마크 → 그 오른쪽에 상자·테두리 없는 메뉴명만 →
맨 오른쪽에 소셜 아이콘**, 그리고 큰 배경 이미지다.

**상단 바**

- 유리 바(반투명 배경 + blur + 아래 테두리)를 **없애고** 배경 사진 위에 글자만 얹었다.
- 좌측 상단 로고: wepic 아이콘(28px) + **"Wepic Live" 흰색 워드마크**(600 weight).
  누르면 예전처럼 홈(소개)으로 간다.
- 메뉴는 **이모지·아이콘을 모두 떼고 이름만** 남겼다
  (`🖼️ 사진 선택` → `사진 선택`, `▶ Demo` → `Demo`, `🛠 관리자 화면` → `관리자 화면` 등).
  상자·테두리 없는 평범한 글자이고, 현재 위치는 **왼쪽에서 자라나는 1.5px 밑줄**
  (참고 사이트 강조색 `#ff3615`, `--menu-accent`)로만 알린다.
- 우측 끝에 **인스타그램 아이콘**(`#link-instagram`). **링크는 아직 `href="#"`**이며
  주소가 정해지면 그 한 곳만 바꾸면 된다.
- 로고가 좌측 상단으로 올라갔으므로 히어로의 **중앙 로고·워드마크·LIVE 배지는 제거**하고
  문구만 왼쪽에 크게 뒀다("Capture Moments, / **Live the Joy**").
  ADMIN 배지는 문구와 겹치지 않게 히어로 **우측 상단**으로 옮겼다.
- 좌측 하위 메뉴(관리자·My사진관리)는 상단 바와 성격이 달라 **상자 형태를 유지**한다.
  상단 바의 `.menu-item`에서 배경·테두리를 뺐기 때문에 `.admin-side-menu .menu-item`에
  다시 지정했다(안 하면 좌측 메뉴가 맨글자로 무너진다).

**배경 — 시네마틱 그레이딩 + 스크림 + 필름 그레인**

- 참고 사이트의 사진을 가져다 쓸 수는 없어(저작권) **배경 사진은 기존 `home-bg.png`를 그대로
  두고**, 그 위에 `.home-scrim` 레이어를 얹어 분위기를 바꿨다.
  사진을 바꾸려면 **`web/public/home-bg.png` 한 파일만 교체**하면 그레이딩이 그대로 적용된다.
- 그레이딩: `backdrop-filter: saturate(0.78) contrast(1.06) brightness(0.84)`.
  `backdrop-filter`는 **뒤에 있는 것(배경 사진)에만** 걸리므로 위에 오는 메뉴·패널 색은
  영향을 받지 않는다.
- 스크림: 위 82% → 가운데 10% → 아래 68%로 흐르는 세로 그라디언트.
  위는 상단 바 흰 글씨, 아래는 패널 글씨를 위해 누르고 **가운데는 사진이 살아 있게** 비웠다.
- `feTurbulence` 기반 **필름 그레인**(opacity 0.05, `mix-blend-mode: overlay`)을 얹어
  사진이 매끈한 CG처럼 보이지 않게 했다. 외부 이미지 없이 data-URI SVG로 자체 포함.
- 쌓임 순서: `.home-scrim`은 `z-index: 0`, 그 위 `.top-menu`(2)·`.hero`(1)·`.home-body`(1).
  `.home-body`에 `position: relative; z-index: 1`을 넣지 않으면 스크림이 본문을 덮는다.

**검증**

- 상단 바 기하: 유리 바 제거 확인(배경 `rgba(0,0,0,0)`, 테두리 0, backdrop `none`),
  로고 좌측 31px·인스타그램 우측 31px로 대칭, 메뉴 글자는 배경·테두리 0 / 14px / 500.
  메뉴 텍스트에 이모지가 남아 있지 않은 것도 확인했다.
- **가독성을 숫자로 확인**: `home-bg.png`의 상단 영역을 캔버스로 샘플링해 휘도를 계산했다.
  스크림 없이 흰 글씨는 **1.99:1**(읽을 수 없음)인데, 그레이딩+스크림 적용 후 **7.61:1**로
  WCAG AA(4.5:1)를 넘는다. 상단이 하늘처럼 밝은 사진이어서 스크림이 반드시 필요했다.
- 메뉴 클릭 → 해당 패널 표시 + `active` 부여, 밑줄은 `.active`에서 `scaleX(1)`로 적용됨.
  (미리보기 창은 화면을 합성하지 않아 transition이 진행되지 않는다 → transition을 끄고
  최종값을 확인했다. 실제 브라우저에서는 정상 동작한다.)
- 모바일(375×812): **로고와 인스타그램은 양끝에 고정**되고 가운데 메뉴명만 가로 스크롤된다
  (스크롤해도 로고 x=14, 인스타그램 right=361 그대로). 콘솔 오류 없음.

**남은 것**: 인스타그램 실제 주소, 그리고 배경 사진을 참고 사이트처럼 시네마틱한 것으로
바꾸고 싶다면 새 이미지 준비(현재 사진은 밝고 요소가 많아 시네마틱한 여백이 적다).

### J-6. ✅ wepic 메인화면(Demo 포함) 좌측 아이콘 줄을 공유화면과 동일하게 (완료, 2026-08-01)

메인 슬라이드쇼(Demo도 같은 화면)에는 좌측 하단에 **다운로드 아이콘 하나만** 있었다.
wepic 공유화면(`share.html`)과 같은 구성으로 맞췄다: **전체화면 · 홈 · 배경음악 · 이전사진 ·
멈춤/재개 · 다음사진 · 사진저장**.

- **홈**(`#btn-photo-home`) — 눌러도, 사진 위 아이콘이 아니라 **상단 메뉴의 홈 아이콘**으로
  나가도 재생 중이던 동영상·배경음악이 함께 멈춘다(아래 항목 참고).
- **배경음악**(`#btn-photo-music`) — 곡이 로드되기 전에는 숨겨둔다(공유화면과 동일하게
  `hidden` 처리). 설정 패널의 "▶/⏸ 재생하기" 텍스트 버튼과 **같은 상태**를 보여주는
  두 번째 표시일 뿐이라, `syncMusicButton()` 한 곳에서 둘 다 갱신한다(흩어져 있던
  `playBtn.textContent = ...` 세 곳을 이 함수 호출로 정리).
- **이전/다음**(`#btn-photo-prev`/`#btn-photo-next`) — `goToPhoto(delta)`를 새로 만들었다.
  wepic 공유화면의 `step()`과 동일하게, 자동 전환 타이머를 끊고 다시 걸어 방금 넘긴 사진이
  곧바로 지나가지 않게 한다.
  자동 전환용 `advance()`(타이머·동영상 종료 시 호출)는 그대로 두고 건드리지 않았다.
- **멈춤/재개**(`#btn-photo-pause`) — 설정 패널의 "⏸ 화면 잠시멈춤" 텍스트 버튼과 **같은
  `slideshowPaused` 상태**를 공유한다. `setSlideshowPaused()`가 두 버튼을 함께 갱신한다.
- 모바일에서 다운로드만 PC 전용으로 숨고(`#btn-download`만 `hover:none`/`pointer:coarse`에서
  숨김), 나머지 6개 아이콘은 그대로 보인다 — 이전에는 `.photo-actions` 전체가 모바일에서
  숨겨져 있어(다운로드만 있던 시절의 규칙을 그대로 물려받음) 전체화면 버튼까지 모바일에서
  사라지는 부작용이 있었다. 공유화면(`share.html`)의 규칙(`#btn-download`만 숨김)과
  똑같이 맞췄다.

**Demo → 홈 이동 시 사운드도 함께 멈추기**

기존에는 `stopEverythingAndGoHome()`(일부 버튼에서만 호출)만 음악·동영상을 멈췄고,
**상단 메뉴의 홈 아이콘**(`selectPanel('about')` → `showHome()`)으로 나가면 음악이 뒤에서
계속 재생됐다. `showHome()`은 패널 전환 때마다 항상 호출되는 공통 경로이므로, 여기에
`stopSlideshowPlayback()`(타이머·동영상·배경음악 정지)을 추가해 **어떤 경로로 홈에 가든**
사운드가 멈추게 했다. `stopEverythingAndGoHome()`은 이제 전체화면 해제 + `selectPanel('about')`
호출만 하는 얇은 함수로 정리했다(정지 로직은 `showHome()` 쪽에 단일화).

**우측 하단 시간·음악이름 색상을 공유화면과 통일**

`.fullscreen-caption`(전체화면일 때 우측 하단에 뜨는 날짜·곡목)이 `rgba(255,255,255,0.88)`
`12px`로 공유화면의 `.share-caption`(`rgba(200,200,200,0.55)` `13px`)과 달랐다. 공유화면
값으로 맞췄다.

**검증**: 로컬에서 Demo를 재생하며 확인했다 — 이전/다음 클릭 시 인덱스가 정확히
순환하고, 멈춤 아이콘과 설정 패널 버튼이 항상 같은 상태를 보여준다. 배경음악을 로드한 뒤
아이콘으로 일시정지/재생을 토글하면 `musicPlaying`과 두 버튼 표시가 함께 바뀐다.
**핵심 확인**: 음악 재생 중 상단 메뉴의 홈 아이콘을 눌렀더니 `ytPlayer` 상태가 재생(1)에서
일시정지(2)로 실제로 바뀌었다(단순 UI 표시가 아니라 실제 재생 정지 확인) — 사진 위 홈
아이콘으로 나갈 때도 동일하게 확인됐다. 모바일 너비(375px)에서 6개 아이콘이 잘리지 않고
다 들어가는 것도 확인했다. 콘솔 오류 없음.

### J-7. ✅ "전체공유"(PIN 없이 공개) + Demo 제거 → "사진 보기" 피드로 대체 (완료, 2026-08-02)

보안 문의("PIN 없이 만들면 다른 사람이 사진을 고칠 수 있냐")에 대한 답으로, 편집은 세션·계정
소유권으로만 지켜지고 PIN은 "보기"만 지킨다는 걸 코드로 확인한 뒤(`apiFramesRename`/
`apiFramesDelete`가 `data.frames.find`로 **호출자 본인 세션**의 액자인지만 확인하고,
`shareCreate`도 클라이언트가 id를 지정할 방법 없이 `sess.data.currentFrameId`만 씀),
"그럼 PIN 없이 전체공개하는 기능도 만들자"는 요청으로 이어졌다.

**① wepic 메인화면 — "전체공유" 체크박스**

- 공유 블록에 체크박스 하나 추가(PIN 행 바로 위). 체크하면 `POST /api/share`·
  `POST /api/share/blob`가 **PIN을 아예 두지 않는다**(`isPublic`이면 `pin: null`).
  기존 PIN 게이트 코드(`verifyPin`/`canViewShare`/`shareAsset`)는 원래 `!manifest.pin`이면
  무조건 통과하도록 짜여 있어서 **한 줄도 안 고쳐도** 전체공개가 작동한다 — PIN을 안
  만드는 쪽만 손보면 됐다.
- 체크박스는 액자를 전환할 때(`frameInfo`에 `isPublic` 추가)·로그인 직후(`/api/status`에
  `sharePublic` 추가) 복원된다. 체크하는 즉시(저장 전에도) PIN 행이 사라져 바로 피드백을 준다.
- 체크를 다시 풀고 저장하면 서버가 **새 PIN을 발급**한다(전체공개였을 땐 `pin`이 없었으므로).
- 기존에 만들어 둔 공유는 전부 `isPublic` 필드가 없다(=false) — 그대로 비공개 유지.

**② Demo 제거 → 상단 메뉴 "사진 보기"로 대체**

Demo(계정 없이 보는 샘플 슬라이드쇼, `/demo/photos.json` 정적 파일)를 없애고, 회원들이
"전체공유"로 공개한 실제 사진을 모아 보여주는 **"사진 보기"** 메뉴로 바꿨다.
"사진 보기"가 처음부터 비어 있지 않도록, 예전 데모 사진 19장을 **실제 R2 공유로 복사해
`isPublic: true`로 등록**했다(관리자 화면의 "사진 보기 예시 등록" 버튼, `POST
/api/admin/seed-showcase` — `env.ASSETS.fetch()`로 `web/public/demo/`의 파일을 그대로
읽어 R2에 넣으므로 원본 파일은 **지우지 않고 남겨둔다**, 재현 가능한 시드 자료로 필요).
멱등이라 이미 등록됐으면 다시 만들지 않는다. 작성자는 "Wepic"으로 표시된다.

카드를 누르면 **같은 화면 안에서 바로 재생**된다(새 탭 아님). 공개 공유는 PIN이 없어
`/shares/<id>/photos.json`을 로그인 없이 그대로 받아올 수 있으므로, 기존 메인 슬라이드쇼
엔진(`boot()`)을 그대로 재사용했다 — J-6에서 만든 이전/다음·멈춤·홈·음악 아이콘, 화면
자동 꺼짐 방지, 세로 사진 블러 배경이 **전부 그대로 적용**된다(새로 만들 게 없었다).
`boot(photos, publicView)`에 `{author, title, musicUrl}`을 실어 보내는 방식으로 확장했고,
`isDemoMode`는 `isPublicViewMode`로 이름을 바꿔 그대로 게스트 판정(편집 UI 숨김)에 쓴다.
(제목은 `loadDisplaySettings()`가 Default 값으로 리셋한 **다음**에 적용해야 유지된다 —
관리자 프레임 모드의 제목 재적용과 같은 이유로, 처음엔 이 순서를 놓쳐 제목이 빈 채로
나오는 버그가 있었고 브라우저로 재확인하다가 잡았다.)

**③ 카드 목록 — 대표사진·작성자·작성일 + 좋아요**

- `GET /api/public/shares`(로그인 불필요)가 `isPublic` 액자를 모아 대표사진·작성자(이름만,
  **이메일은 절대 내려주지 않는다**)·사진 수·좋아요 수·내가 눌렀는지를 돌려준다.
- 개인 프로젝트 규모라 서버 페이지네이션은 과함 — 한 번에 다 받아와서 9개씩 배치로
  그리고, `IntersectionObserver`로 하단에 닿으면 다음 배치를 그린다("계속 아래로
  나오는" 무한 스크롤처럼 보이지만 실제로는 이미 받아온 목록을 나눠 그리는 것).
- **좋아요는 D1**(`share_likes` 테이블, `(share_id, user_id)` UNIQUE)로 뒀다 — 요청대로
  향후 댓글 기능을 고려한 선택이다. 좋아요를 R2의 photos.json에 두면 좋아요 하나 누를
  때마다 매니페스트 전체를 다시 써야 해서 낭비인 것도 이유. 댓글을 추가할 땐 같은 모양
  (share_id + user_id + 내용)의 별도 테이블만 두면 된다.
- **로그인한 회원 누구나** 좋아요를 누를 수 있다(본인이 올린 사진도 포함, 제한 없음).
- 비로그인 상태에서 누르면 API를 부르지 않고 "로그인한 사용자만 좋아요와 댓글을 남길 수
  있습니다" 토스트를 띄운 뒤 로그인 화면으로 보낸다.

**검증**

- 로컬에 테스트 관리자·회원 D1 행 + KV 세션을 직접 만들어(curl + `wrangler kv key put
  --local`) API를 끝까지 확인했다: 시드 등록(1회차 성공 → 2회차 `alreadySeeded`), PIN 없이
  `/f/<id>`·`/shares/<id>/photos.json` 200 확인, 전체공유로 공유 생성 시 `pin: null` 응답,
  비공개로 되돌리면 새 PIN 발급 + 피드에서 즉시 사라짐, 비로그인 좋아요 401, 로그인 회원
  좋아요 추가/취소(카운트 1→0), 전체공유가 아닌 액자에 좋아요 시도 404.
  (중간에 curl의 `-F @경로` 멀티파트 업로드가 Git Bash POSIX 경로에서 자꾸 끊겨
  `status=000`이 났는데, 원인은 서버가 아니라 curl의 경로 처리였다 — Windows 경로로
  바꾸니 정상 동작해 확실히 구분했다.)
- 브라우저에서 "사진 보기" 클릭 → 카드 렌더(대표사진·"Wepic · 날짜 · 사진 19장"·♡0) →
  좋아요 누르면(비로그인) 토스트 + 로그인 화면 이동 확인 → 카드 클릭 → 슬라이드쇼가 같은
  화면에서 재생되고 배지에 "공개 공유 · Wepic" 표시, `share-block`은 게스트라 숨겨짐,
  제목·배경음악이 그 공유의 값으로 정확히 반영되는 것까지 확인(위의 순서 버그를 여기서
  잡았다). 이전/다음/멈춤 아이콘도 그대로 동작. 콘솔 오류 없음.
- 전체공유 체크박스: 체크 시 PIN 행이 즉시 숨는 것을 DOM으로 확인.

**남은 것**: 원격(운영) D1에도 `schema.sql`을 다시 적용해야 `share_likes` 테이블이
생긴다(`npx wrangler d1 execute wepic-db --remote --file=./schema.sql`) — 배포 직후
관리자가 "사진 보기 예시 등록" 버튼을 한 번 눌러야 실제 서비스에도 예시 콘텐츠가 생긴다.
댓글 기능은 이번에 넣지 않았다(향후 로드맵 D 항목 — `share_likes`와 같은 모양으로 확장).

### J-8. ✅ wepic 용어 정립 · 화면 재배치 · Spotify · 회원탈퇴 · Quota (완료, 2026-08-02)

**용어**: 컨텐츠 하나를 만드는 것을 이제 **"wepic을 만든다"**고 부른다(문서·UI 공통).

**① wepic 주소를 "링크변경 반영" 위에 표시**

wepic이 만들어지면 공유 블록의 버튼 **바로 위**에 주소를 보여준다(`#share-url-inline`).
눌러서 새 탭으로 바로 열 수 있다. `setShareLinkState()`가 `#share-url` 값을 읽어 그리므로,
호출부에서 **share-url을 먼저 채운 뒤** 이 함수를 부르도록 순서를 맞췄다(안 그러면 직전
액자의 주소가 남는다). 로그인 직후에도 보이도록 `/api/status`에 `shareUrl`을 추가했다.

**② 메인화면 설정 순서 변경 + "추가옵션"**

`사진 목록 → 화면 표시 → 배경음악 → 공유` 순으로 바꾸고, 자주 안 바꾸는
**사진 방향·재생 설정**은 "추가옵션" 버튼 안으로 접어 넣었다(기본 접힘, `aria-expanded` 반영).
하단 링크(사진 다시 선택하기 등)는 그대로 맨 아래 유지. 배경음악 라벨에서 **"(YouTube)"를
제거**하고 입력칸 안내도 "음악 링크 붙여넣기"로 바꿨다. 다만 그 칸은 여전히 YouTube 링크만
받으므로, Spotify 링크를 붙여넣으면 "Spotify 곡은 옆의 Spotify 버튼으로 골라주세요"라고
안내한다(예전엔 그냥 "올바른 YouTube 링크가 아닙니다"라 뭘 하라는 건지 알 수 없었다).

**③ Spotify 배경음악 (30초 미리듣기)**

YouTube 재생은 그대로 두고, 옆에 **Spotify 버튼**을 추가해 팝업에서 곡을 검색·선택한다.

- 서버: `GET /api/spotify/search` — **Client Credentials** 플로우(사용자 Spotify 로그인 불필요)로
  앱 토큰을 받아 검색한다. 토큰은 Worker 메모리에 만료 전까지 캐시한다.
- **30초 미리듣기(preview_url)만 쓴다.** 전체 곡 재생은 Spotify Web Playback SDK + 유료 계정이
  필요해 이 앱에는 맞지 않는다. 팝업에 "30초 미리듣기만 제공합니다"라고 명시했다.
- **미리듣기가 없는 곡은 서버에서 걸러낸다**(권리사·앱 등록 시점에 따라 `preview_url`이 null인
  곡이 많다). 결과가 비면 "N곡을 찾았지만 미리듣기를 제공하는 곡이 없습니다"라고 이유를 알려준다.
- 재생은 `<audio loop>`다(30초라 반복해야 배경음악 구실을 한다). `musicUrl` 한 칸에 YouTube
  링크와 Spotify 미리듣기 URL이 모두 들어올 수 있어 **주소(p.scdn.co)를 보고 어느 쪽인지
  판단**한다 — 별도 필드를 두지 않아 기존 액자와 그대로 호환된다.
- 곡목은 주소에서 알 수 없어 매니페스트에 **`musicTitle`을 함께 저장**한다(YouTube는 플레이어가
  알려주므로 불필요하지만 같이 저장해도 무해하다). 공유화면도 이 값을 읽어 곡목을 표시한다.
- 공유화면의 "기본 무음 → ▶로 소리 켜기" 규칙을 Spotify에도 똑같이 적용했다(muted로 시작).
- **키가 없으면 503 + 안내**를 준다. 처음엔 throw해서 스택 트레이스가 그대로 나오는 500이었는데,
  YouTube는 멀쩡히 되는 상황이라 치명적 오류처럼 보이면 안 되므로 고쳤다.
- ⚠️ **`SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET`을 등록해야 동작한다**(미등록 시 버튼은
  안내만 띄우고 YouTube는 정상). https://developer.spotify.com/dashboard 에서 앱 생성.

**④ 버그 수정: "사진 보기" 카드는 wepic 공유화면으로**

카드를 누르면 **메인화면 슬라이드쇼**가 열리던 것을 `/f/<id>`(**wepic 공유화면**)로 바꿨다.
메인화면은 "내 사진을 편집하는 화면"이라 남의 wepic을 볼 자리가 아니다(설정 패널·액자 선택이
같이 보였다). 이에 따라 J-7에서 넣었던 `isPublicViewMode`·`publicView` 분기와 공개 보기
배지를 **전부 제거**했다 — 공유화면이 원래 그 역할을 하도록 만든 화면이라 더 단순해졌다.

**⑤ 회원탈퇴**

회원정보 화면의 로그아웃 옆에 **회원탈퇴**를 두었다. 누르면 팝업이 뜨면서
"회원탈퇴를 하게 되면 **사용된 계정과 만들었던 Wepic 컨텐츠가 삭제됩니다**"를 먼저 보여주고,
**무엇이 지워지는지 요약**(만든 wepic 수·사진 수·용량)도 함께 띄운다. 확인해야 실행된다.

지우는 것: ① 본인이 만든 wepic 전부(R2, `ownerUserId`로 판별) ② 좋아요 기록 ③ users 행
④ 세션(쿠키까지 만료). 서버도 `confirm: 'DELETE'`를 요구해 실수 호출을 막는다.

**⑥ 상단 로그인 이름 → 로그아웃**

예전에는 눌러도 아무 일이 없었다. 이제 "로그아웃하시겠습니까?" 확인 후 로그아웃한다.
로그아웃 로직은 세 곳에서 쓰므로 `doLogout()`으로 묶었다.

**⑦ 로드맵 추가**: K(인스타그램 자동 포스팅) · L(WAF 레이트리밋) 항목 신설.

**⑧ 개인별 저장용량 Quota (기본 100MB)**

- `users.quota_bytes` 컬럼 추가(**NULL = 기본값 100MB 따름**). 기본값을 바꿀 때 기존 회원을
  전부 UPDATE하지 않아도 되도록 일부러 NULL을 허용했다. 관리자가 늘려주면 그때 값이 채워진다.
- ⚠️ 이미 만들어진 DB에는 `CREATE TABLE IF NOT EXISTS`가 건너뛰어져 컬럼이 안 생긴다 →
  **`migrations/002_add_quota.sql`을 1회 실행**해야 한다(SQLite에 `ADD COLUMN IF NOT EXISTS`가
  없어 schema.sql에 넣으면 재실행 때마다 오류로 멈추므로 별도 파일로 뺐다).
- 사용량은 R2를 훑어 `ownerUserId`가 맞는 액자의 파일 크기를 합산한다(집계 테이블 없음).
- **업로드 전에** 막는다(쓰고 나서 되돌리면 이미 용량을 쓴 상태가 된다). 갤러리 업로드는
  파일 크기를 미리 아니 한 번에 검사하고, 구글 포토는 크기를 미리 알 수 없어 **한 장씩 받으며
  누적**하다 한도에 닿으면 멈추고 "N장만 저장했다"고 알려준다. 동영상도 남은 용량을
  상한으로 넘겨 초과분은 포스터만 남긴다.
- **"링크변경 반영"으로 같은 액자를 덮어쓸 때는 그 액자의 기존 용량을 빼고 계산**한다 —
  안 빼면 같은 사진을 다시 올릴 때 두 배로 계산돼 억울하게 막힌다.
- 회원정보 화면에 `사용량 / 한도 (%)`와 막대를 표시한다(90% 이상이면 붉게).

**⑨ 관리자 회원관리 화면**

좌측 관리자 메뉴에 **👥 회원관리**를 추가했다. 회원 목록(이름·제공자·권한·이메일·가입일·
최근 로그인)과 **개인별 Quota·현재 사용량·사용률 막대**를 함께 보여주고, MB 단위로 **용량을
바로 수정**할 수 있다(비우면 기본값으로 복귀). 사용량은 **R2를 한 번만 순회**해 회원별로
집계한다(회원마다 훑으면 N배 느려진다).

**검증** (로컬에 테스트 관리자·회원 D1 행 + KV 세션을 직접 만들어 curl·브라우저로 확인)

- 화면 순서: `사진 목록 → 화면 표시 → 배경음악 → 공유 → 추가옵션` 확인, 추가옵션 안에
  사진 방향·재생 설정만 들어있고 기본 접힘, 토글 시 캐럿·`aria-expanded`까지 바뀜.
- wepic 주소 줄이 `share-btn-row`보다 **위**에 있고(DOM 순서 확인), 링크가 없으면 사라짐.
- 카드 클릭 → 실제로 `/f/wepic-showcase`로 이동하고 `.share-view`가 뜨며 메인화면
  요소(`#screen-slideshow`·`.info-pane`)는 없음.
- **Quota**: 1MB로 낮춘 뒤 2MB 업로드 → **413 + 한국어 안내**. 10MB로 올린 뒤 2MB 업로드 →
  성공하고 사용량 2.0MB로 반영. **같은 액자에 재업로드해도 4MB로 이중 계산되지 않음**(2.0MB 유지).
- **회원탈퇴**(가장 조심한 부분): `confirm` 없이/틀린 값으로 호출 → **400이고 계정·wepic 그대로**.
  올바른 확인으로 실행 → users 행 삭제·좋아요 삭제·본인 wepic 404·세션 무효화(`loggedIn:false`)
  확인, 그리고 **관리자 계정과 남의 전체공유(시드)는 그대로 살아있음**(200)을 함께 확인했다.
- Spotify: 팝업에 30초 안내 표시, 비로그인 검색은 401, 키 미설정 시 **503 + 안내 문구**.
- 로그인 이름 클릭 → "로그아웃하시겠습니까?" 확인, 취소하면 로그인 유지.
- 콘솔 오류 없음. 검증 후 테스트 회원·세션·임시 파일은 모두 정리했다.

**배포 시 필요한 것**: ① 원격 D1에 `migrations/002_add_quota.sql` 1회 실행
② Spotify를 쓰려면 `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET` 시크릿 등록.

### J-9. ✅ "사진선택" 섹션 정리 — 액자 리스트박스 제거·랜덤 이름·팝업 제거 (완료, 2026-08-02)

메인화면의 성격을 분명히 했다: **여기는 새 wepic을 만드는 화면**이고, 예전 wepic을 찾아
관리하는 것은 **My사진관리**가 한다. 그래서 겹치던 UI를 걷어냈다.

**① 액자 리스트박스 제거 → 이름 입력칸**

- `<select id="frame-select">`(예전 wepic 골라 불러오기)를 없애고 **텍스트 입력칸**만 남겼다.
  이제 메인화면에서 남의/예전 wepic을 불러오는 경로가 없다(My사진관리에서 연다).
- 이름은 처음부터 **"색깔 + 동물"로 자동 제안**된다(예: "파란 여우", "검은 다람쥐").
  색깔 16개 × 동물 18개 조합이라 겹칠 일이 드물고, 이름 짓느라 멈칫하지 않아도 된다.
- **연필(✎)** — 이름 입력칸에 포커스를 주고 전체 선택해 바로 고쳐 쓸 수 있게 한다.
- **wepic을 만든 뒤에는 이름칸과 연필이 모두 disabled**가 된다(만들어진 wepic은 이름 고정).
  삭제하거나 "+"로 새로 시작하면 다시 열리고 새 이름이 뽑힌다.
- **"+"** — 새 wepic 시작. 서버에 빈 액자를 미리 만들지 않고(예전에는 만들었다) 선택만
  해제한 뒤 이름을 새로 뽑는다. 실제 액자는 사진을 올려 만들 때 생성된다.
- 화면에서 정한 이름은 업로드 시 `frameName`으로 함께 보내고, 서버는 **새로 만드는
  액자에만** 그 이름을 쓴다(이미 있는 액자의 이름은 바꾸지 않는다).

**② "공유" → "사진선택"으로 이름 변경**, 섹션 구성도 다시 짰다:

`이름 + 아이콘 → wepic 주소 → 전체공유 → PIN → 사진 고르기 아이콘 → 링크변경 반영(맨 아래)`

**③ 사진 고르기 링크를 이 섹션으로 올리고 아이콘화**

화면 맨 아래 글자 링크였던 것을 "사진선택" 섹션 안(전체공유·PIN 아래)으로 옮기고
아이콘으로 바꿨다: **🔄**(다시 선택) · **➕**(사진 추가) · **➖**(사진 제외).
구글 로그인이면 구글 포토용, 그 외에는 갤러리용 아이콘이 나오는 기존 분기는 그대로다.
`btn-exclude`는 예전에 `textContent`를 "제외 취소"로 바꿨는데, 아이콘 버튼에서는 그러면
아이콘이 사라진다 → **`.active` 클래스 + 툴팁**으로 상태를 표시하도록 고쳤다.

**④ 로그아웃 링크 제거** — 상단 메뉴의 내 이름을 누르면 로그아웃되므로(J-8 ⑥) 중복이었다.

**⑤ 링크 생성 팝업 제거**

wepic을 만들 때 뜨던 모달을 통째로 없앴다. 주소는 섹션 안 "wepic 주소" 줄에 바로 보이고
복사·삭제는 이름 옆 아이콘(📋·🗑)으로 하므로 팝업이 할 일이 없었다.
팝업 안에 있던 `#share-url` 입력칸도 함께 사라져서, 주소를 **`currentShareUrl` 변수 하나로**
관리하도록 정리했다(복사 폴백은 임시 textarea를 만들어 처리).

**검증**

- 섹션 순서·이름("사진선택")·리스트박스 제거·팝업 요소 제거·로그아웃 링크 제거 확인.
- "+"를 여러 번 눌러 이름이 매번 다르게 "색깔 동물" 형식으로 뽑히는 것 확인.
- 연필은 입력칸을 전체 선택한다(미리보기 창은 OS 포커스가 없어 `activeElement`는 body로
  남지만 `selectionRange [0,6]`으로 실제 동작을 확인했다 — 실제 브라우저에서는 포커스도 간다).
- **브라우저 FormData 경로**로 "초록 다람쥐" 이름의 wepic을 만들어, 응답·`/api/frames`·
  R2 매니페스트 세 곳 모두에 한글이 깨지지 않고 저장되는 것을 확인했다.
  (curl로 보냈을 때는 이름이 깨졌는데, 원인은 서버가 아니라 **Git Bash/curl의 한글 인코딩**이었다
  — 브라우저 경로에서는 정상이라 실제 사용에는 문제가 없다.)
- 만든 뒤: 이름칸·연필 disabled, 주소 줄 표시, "만들기" 숨김·"반영" 표시, 복사·삭제 아이콘 표시.
  삭제 뒤: 이름칸 다시 열리고 새 이름 제안, 주소 줄 사라지고 "만들기" 복귀.
- 제거한 요소를 참조하던 코드 2곳(`btn-logout`, `reconnect-dot`)이 남아 있어 스크립트가
  깨질 뻔했는데, 정리 후 콘솔 오류 없음을 확인했다. 세 JS 파일 문법 검사도 통과.

### J-10. ✅ 액자 개념 제거 · "공유하기" 단일 버튼 · 사진 보기 인라인 재생 (완료, 2026-08-02)

**① "사진선택" 섹션에서 액자(이름) 기능 제거**

메인화면에서 액자 이름을 만들고 고치는 UI(입력칸·`+`·연필)를 **전부 없앴다**.
사용자가 만든 wepic을 고르는 것은 My사진관리가 하므로 메인화면에는 필요가 없었다.
다만 My사진관리·관리자 목록에서 "액자 1, 액자 2"보다 알아보기 쉽도록, **"색깔 + 동물"
이름은 화면에 노출하지 않고 app.js가 조용히 붙여준다**(J-9에서 만든 생성기를 그대로 재사용).

**② 버튼을 "공유하기" 하나로**

"실시간 공유 링크 만들기"/"링크변경 반영" 두 버튼을 **`공유하기` 하나**로 합쳤다.
아직 안 만들었으면 만들고, 이미 만들었으면 같은 링크에 반영한다(`currentShareUrl` 유무로 판단).
**누르면 그 아래에 wepic 주소가 나타난다.**

**③ 섹션 순서 재배치** (요청 순서 그대로)

```
사진선택
  🔄 ➕ ➖ │ 📋 🗑      ← 사진 고르기 + 링크 복사·삭제를 한 줄에 모음
  PIN
  [공유하기]
  wepic 주소            ← 공유하기를 누르면 나타난다
  ☐ 전체공유
```

**④ 추가옵션으로 옮김 / 제거한 것**

- **시계·날씨 표시** 체크박스 → 추가옵션 안으로(사진 방향·재생 설정과 함께).
- **"⏸ 화면 잠시멈춤" 버튼 제거** — 사진 위 좌측 아이콘 줄의 ⏸ 버튼이 같은 일을 한다.
- **"계정 다시 연결하기" 링크 제거** — 토큰이 만료되면 어차피 로그인 화면으로 보낸다.

**⑤ "사진 보기"에서 카드를 눌러도 홈페이지 메뉴가 유지되게**

카드를 누르면 `/f/<id>`로 **페이지를 통째로 옮겨** 홈페이지 상단 메뉴가 사라지던 것을 고쳤다.

- 보여줄 화면은 **wepic 공유화면이어야 하고**(메인화면은 내 사진을 편집하는 곳이라 맞지 않는다),
- 동시에 **홈페이지 메뉴는 계속 보여야 한다**.
- → 두 조건을 함께 만족시키려고 **공유화면을 하위 프레임 안 `<iframe>`으로 끼워 넣었다.**
  `allow="fullscreen; autoplay; encrypted-media"`를 줘야 공유화면의 전체화면 버튼과
  배경음악(YouTube·Spotify)이 그대로 동작한다.
- "← 목록으로" 버튼으로 돌아가며, 그때 **iframe의 src를 비워** 뒤에서 음악이 계속
  흐르지 않게 한다. "새 창으로 열기" 링크도 함께 뒀다.
- 공유화면의 **"홈으로"(🏠) 버튼은 iframe 안에서는 숨긴다** — 이미 홈페이지 위에 떠 있는
  셈이라 누르면 iframe 안에 홈페이지가 또 열려버린다(`window.top !== window.self`로 판별).
  단독으로 `/f/<id>`를 열었을 때는 그대로 보인다.

**검증**

- 사진선택 섹션 순서: `아이콘줄 → PIN → 공유하기 → 주소 → 전체공유` 확인.
  아이콘 7개(다시선택·추가·갤러리 2종·제외·링크복사·링크삭제) 확인, 버튼 문구 "공유하기" 확인,
  액자 이름 UI 3개(`frame-name`·`+`·연필) 모두 제거됨 확인.
- info-pane 순서: `사진 목록 → 화면 표시 → 배경음악 → 사진선택 → 추가옵션`,
  추가옵션 안에 `사진 방향 · 재생 설정 · 동영상 소리 · 시계·날씨` 4개 확인.
  "화면 잠시멈춤"·"계정 다시 연결하기" 제거 확인.
- **사진 보기 카드 클릭**: `location.pathname`이 `/`에서 **바뀌지 않고**, 상단 메뉴·홈
  프레임이 그대로 보이며, iframe이 `/f/wepic-showcase`를 로드해 **그 안에 `.share-view`와
  공유화면 아이콘 6개**가 실제로 그려지는 것을 확인했다(메인화면 요소는 없음).
  "목록으로"를 누르면 목록이 돌아오고 iframe src가 비워졌다.
- iframe 안에서는 홈 버튼이 `display:none`, 단독 실행 시에는 보이는 것을 각각 확인.
- 제거한 요소를 참조하던 코드가 남지 않았는지 id별로 전수 확인(0건), 문법 검사 통과,
  콘솔 오류 없음.

### J-11. ✅ 음악찾기(iTunes Search API로 교체) + wepic 실시간 댓글·좋아요 (완료, 2026-08-02)

**① 배경음악 검색을 Spotify → iTunes Search API로 교체**

- **API 키·앱 등록이 전혀 필요 없다.** `https://itunes.apple.com/search`는 공개
  엔드포인트라 시크릿을 둘 필요가 없어졌다(`SPOTIFY_CLIENT_ID/SECRET` 안내를 wrangler.toml에서
  제거). 갈아탄 결정적 이유는 **미리듣기 제공률**이다 — Spotify는 2024년 말 정책 변경으로
  신규 앱에 `preview_url`을 내려주지 않는 곡이 많아 검색 결과가 자주 비었는데,
  실제로 확인해보니 iTunes는 `아이유` 검색에서 **25곡 중 25곡** 모두 미리듣기가 있었다.
- 엔드포인트도 `/api/spotify/search` → **`/api/music/search`**로 바꿨고, UI 문구에서
  특정 서비스 이름을 드러내지 않는다(버튼 = **"음악찾기"**, 팝업 제목 = "음악찾기").
  다만 검색 출처를 완전히 숨기는 것은 정직하지 않으므로 팝업 맨 아래에 아주 작게
  "검색 제공: iTunes"만 적었다(원치 않으면 그 한 줄만 지우면 된다).
- ⚠️ **처음엔 Worker가 대신 호출하게 만들었는데 배포 후 항상 실패했다** — 자세한 원인과
  수정은 아래 J-12 참고. 결론적으로 **브라우저에서 직접(JSONP)** 부르도록 바꿨다.
- 미리듣기 주소 판별을 `p.scdn.co` 한 곳에서 **호스트 화이트리스트 정규식**으로 넓혔다
  (`mzstatic.com`·`itunes.apple.com`, 그리고 **예전에 Spotify로 만들어 둔 wepic이 계속
  재생되도록 `scdn.co`도 유지**). `^https?://([\w-]+\.)*(...)/`로 앵커를 걸어
  `evil.com/itunes.apple.com/...` 같은 가짜 주소는 걸러진다(테스트로 확인).
- 검색어를 한국 스토어(`country=KR`) 기준으로 보내 국내 곡·한글 검색이 잘 나오게 했다.

**② wepic마다 실시간 댓글 + 좋아요**

- 저장은 **D1**(`share_comments`). 원래 로드맵 D는 매니페스트에 넣는 안이었는데, 글 하나
  달릴 때마다 photos.json 전체를 다시 써야 하고 동시 작성 시 서로 덮어쓸 수 있어 표로 바꿨다.
- **로그인하지 않아도 쓸 수 있다.** 로그인했으면 회원 이름, 아니면 **"색깔 + 동물" 별명**
  (예: "초록 코알라")이 붙는다. 별명은 브라우저에 심는 `wvid` 쿠키 값에서 **계산해서** 만든다
  (해시 → 색·동물 인덱스) — 별명 표를 따로 저장하지 않아도 **같은 브라우저면 늘 같은 별명**이
  나온다. 새로고침해도 이름이 유지되는 것을 확인했다.
  - ⚠️ 구현 중 버그: 해시를 `h >> 8`로 썼더니 h가 2^31을 넘을 때 **음수 인덱스**가 되어
    이름이 "검은 undefined"로 나왔다 → 부호 없는 시프트 `>>>`로 고쳤다.
- **좋아요도 비로그인 허용**으로 바꿨다. 공유화면 방문자 대부분이 비로그인이라 로그인을
  요구하면 사실상 아무도 못 누른다. 중복은 회원이면 user_id, 아니면 `wvid` 쿠키로 막는다.
  기존 `share_likes`는 `user_id NOT NULL`이라 제약을 바꾸려면 표를 다시 만들어야 해서,
  비로그인용은 **별도 표**(`share_likes_anon`)로 두고 **개수는 두 표를 합해서** 센다.
- **"동시에 모두 본다"는 폴링으로 구현했다.** 진짜 푸시(WebSocket)는 Cloudflare에서 Durable
  Objects가 필요해 지금 구성(KV·D1·R2)보다 무거워진다. 댓글창을 열어둔 동안 **3초**,
  닫아두면 20초 주기로 **새로 달린 것만**(`?after=마지막id`) 받아온다 — 매번 전체를 다시
  받지 않아 가볍고, 체감상 거의 실시간이다. 새 글은 잠깐 배경이 밝아지며 들어온다.
- **PIN이 걸린 wepic은 댓글·좋아요도 막는다**(`requireViewableShare`가 `canViewShare`를 재사용).
  링크만 알면 남의 비공개 wepic에 글을 남길 수 있으면 안 된다 — 실제로 401을 확인했다.
- 도배 방지: 같은 회원/방문자 기준 **1분에 10개**까지(KV 카운터).
- 글자 수 **50자** — 입력칸 `maxlength`와 **서버 검사** 양쪽에 걸었다(51자는 400, 50자는 통과).
- **나중에 보는 사람도 글을 볼 수 있다** — 표에 남으므로 새로고침·재방문 후에도 그대로 보인다.
- 회원탈퇴 시: 본인이 쓴 댓글·좋아요는 물론, **본인이 만든 wepic에 남들이 달아둔 댓글·좋아요도**
  wepic과 함께 지운다(고아 데이터가 남지 않게).
- "사진 보기" 카드에도 **댓글 수**를 함께 표시한다(들어가 보지 않아도 이야기가 있는지 알 수 있게).

**검증**

- 음악찾기: 키 없이 25/25곡 미리듣기 확인, 비로그인 401·빈 검색어 400·옛 Spotify 경로 404,
  브라우저에서 "아이유" 검색 → 결과·앨범커버 표시 → 곡 선택 시 `music-url`에 미리듣기 주소가
  들어가고 **`<audio>`가 `readyState:4`·에러 없이 실제 재생**되는 것까지 확인.
  UI 어디에도 "Apple" 문자열이 없는 것도 확인했다.
- 댓글: 비로그인으로 한글 댓글 작성 → "초록 코알라"로 표시, **쿠키를 보내지 않은 다른
  방문자**가 쓴 글이 **폴링으로 4.5초 안에 자동으로 들어오는 것**을 확인(= 실시간 동작),
  새로고침 후에도 3개가 그대로 남고 내 별명도 유지, 좋아요 누름/취소(1↔0) 확인,
  PIN wepic은 목록·작성·좋아요 모두 401이고 DB에 글이 들어가지 않은 것을 확인.
- 세 JS 파일 문법 검사 통과, 콘솔 오류 없음. 테스트 데이터는 모두 정리했다.

**배포 시 필요한 것**: 원격 D1에 `migrations/003_comments.sql` 1회 실행.
**Spotify 시크릿은 이제 필요 없다**(등록해 두었다면 지워도 된다).

### J-12. ✅ 음악찾기가 배포 후 항상 실패한 문제 — 브라우저 직접 호출로 전환 (완료, 2026-08-02)

**증상**: 로컬에서는 잘 되던 음악찾기가 배포 후에는 **한 번도 성공하지 못하고** 매번
"음악 검색 요청이 잠시 많습니다"만 떴다.

**원인**: 이 검색 API는 **IP당 분당 약 20회** 제한이다. Worker가 대신 호출하면
- 우리 앱의 **모든 사용자가 Cloudflare의 같은 출구 IP를 공유**하고,
- 그 출구 IP는 **같은 API를 쓰는 다른 Worker들과도 공유**된다.

그래서 한도가 사실상 늘 소진돼 있어 매번 거부당했다.
**로컬(`wrangler dev`)에서는 집 IP로 나가기 때문에 잘 됐고, 그래서 배포 후에야 드러났다** —
"로컬에서 됐다"가 이 경우에는 아무 보장이 아니었다.

**수정**: 검색을 **브라우저에서 직접** 하도록 바꿨다. 그러면 사용자마다 자기 IP의 한도를
쓰므로 공유 IP 문제가 사라진다. 이 API는 CORS 헤더를 주지 않지만(그래서 처음에 Worker를
거쳤다) **JSONP(`callback=`)를 지원**해서 브라우저에서 쓸 수 있다.

- `searchMusicDirect()` — `<script>`를 붙여 JSONP로 받아오고, 응답·오류·시간초과(8초) 어느
  경우든 **콜백과 script 태그를 반드시 정리**한다(누수 없음을 테스트로 확인).
- 서버 경로(`/api/music/search`)는 **폴백으로 남겨두었다** — 확장 프로그램이나 사내망이
  외부 스크립트를 막는 환경에서는 서버를 거쳐 한 번 더 시도한다.
- 오류 메시지에 **상태코드를 반드시 남기도록** 고쳤다. 예전에는 403과 429를 뭉뚱그려
  "요청이 많습니다"로만 보여줘서, 실제로는 IP 문제인데 원인을 알 수 없었다.

**검증**
- 브라우저에서 `searchMusicDirect('아이유')` → **473ms에 25곡**, 미리듣기 25/25.
  호출 후 `__wepicMusicCb*` 콜백과 `script[src*=itunes]` 태그가 **모두 정리된 것**을 확인.
- UI에서 "BTS" 검색 → 25곡(방탄소년단) 표시. **로그아웃 상태에서도 검색된다** —
  서버(로그인 필요)를 거치지 않는다는 증거다.
- 곡 선택 → `music-url`에 미리듣기 주소가 들어가고 `<audio>`가 `readyState:4`·에러 없이 재생.
- JSONP를 일부러 실패시키면 서버 폴백으로 넘어가고, **두 실패 이유를 함께** 보여준다.

**배운 것**: 외부 API를 Worker로 프록시할 때는 **"IP당 한도"가 있는지** 먼저 확인해야 한다.
있으면 프록시가 곧 병목이 되고, 로컬 테스트로는 절대 드러나지 않는다.

### J-13. ✅ 음악 버튼 복구 · 문구 전면 갱신 · 디자인 시스템 도입 (완료, 2026-08-03)

사용자 요청 7건을 한 번에 반영했다.

**① 버그 — 음악찾기로 만든 wepic에서 음표 버튼이 사라졌다**

- 재현: `musicUrl`이 iTunes 미리듣기 주소인 wepic을 만들면 `#btn-music`이 `display:none`.
- 원인: `startPreviewMusic()`이 버튼을 `flex`로 켠 **직후** `initMusic()`이 실행되고,
  `ytId(미리듣기주소)`가 `null`이라 **버튼을 다시 숨겨버렸다**. `initMusic()`은
  YouTube 배경음악 전용 함수인데 미리듣기에도 불려서 생긴 문제.
- 수정 (`share.js`) — 두 곳을 함께 막았다.
  - 호출부: `if (musicUrl && !isPreviewUrl(musicUrl) && !playerPromise) initMusic();`
  - 함수 안: 미리듣기가 재생 중이면(`usingPreview()`) 버튼을 숨기지 않는다.
- 검증: 버튼이 보이고 **무음으로 시작**(`soundOn:false, muted:true`) → 한 번 누르면
  `muted:false, readyState:4`로 재생 → 다시 누르면 무음. YouTube 경로도 그대로 동작.

**② 문구 전면 갱신** — 예전 "구글 포토에서 사진 올리기" 시절 표현을 현재 제품에 맞게 고쳤다.

- 소개 패널을 다시 썼다: eyebrow(`wepic live — Real-time Audio-Visual Frame Platform`) +
  헤드라인 + 기능 카드 3장(실시간 반영 · 음악과 함께 · 같이 보는 재미).
- 로그인 안내는 "구글은 포토에서 골라오고, 카카오·네이버는 갤러리에서 올린다"로 정리.
- 사진 선택 패널에 `Step 1 — 사진 고르기` 라벨과 안내문을 붙이고, 단계 설명을
  명령문("클릭") 대신 사람 말투로 바꿨다.

**③ 배경 사진 교체 + 그에 맞춘 그레이딩 재조정**

- `web/public/home-bg.png`를 새 이미지(TV가 있는 밝은 거실)로 교체.
- 예전 값(`brightness 0.84`)은 **밝은 사진**에서는 흰 글씨가 묻힌다 → 눈대중이 아니라
  사진의 실제 평균 밝기에서 계산해 맞췄다:
  `saturate(0.72) contrast(1.04) brightness(0.62)` + 차콜 그라디언트(위 0.90 → 가운데 0.30 →
  아래 0.88) + 우하단 코랄 radial.
- 계산 결과 대비: 상단 바 흰 글씨 **17.6:1**, 히어로 문구 **11.7:1**(서브문구 7.2:1),
  패널 영역 **10.4:1** — AA(4.5:1)를 넉넉히 넘기면서 사진의 형태·색은 살아 있다.

**④ 회원정보 — 고칠 수 있는 건 이메일뿐임을 눈으로 보이게**

- 이름을 입력칸에서 **읽기 전용 항목**으로 내리고(`#me-name`은 이제 `<span>`),
  **저장 버튼을 이메일 입력칸 바로 옆**에 붙였다(`.me-email-row`).
- `PUT /api/me`는 여전히 `name`을 함께 받으므로, `app.js`가 현재 이름을 `meName`에
  담아두고 저장 시 그대로 되돌려 보낸다(서버 계약은 안 건드렸다).

**⑤ 좌측 하위 메뉴를 상단 바와 같은 결로**

  이름만 남기고 현재 항목은 **왼쪽 세로선**(코랄)으로 표시. 좁은 화면에서는 가로로 누우며
  세로선 대신 **아래 밑줄**로 바뀐다.
- J-5에서 "좌측 메뉴는 상자 형태를 유지한다"고 적었던 결정을 여기서 뒤집었다.

### J-15. ✅ 함께 보기 안내 · 좋아요·댓글 실시간 팝업 · 빈화면 모드 (완료, 2026-08-04)

**① 함께 보기 안내 (사진은 맞추지 않는다)**

처음에는 "모두 같은 사진을 동시에" 방향을 검토했으나, 사용자 판단으로 **사진 동기화는 하지
않고 안내만** 넣기로 정했다. 그래서 재생 위치를 맞추는 로직은 넣지 않았다(이전/다음 버튼과
충돌하지 않고, 동영상이 섞인 wepic도 그대로 동작한다).

- 새 표: `share_presence(share_id, visitor_id, first_seen, last_seen)` — `migrations/004_presence.sql`
- 새 API: `POST /api/wepic/:id/presence` — 하트비트(25초)를 받아 내 행을 UPSERT하고
  `{viewers, joined, now}`를 돌려준다. 최근 45초 안에 갱신된 행만 접속 중으로 센다.
- **KV가 아니라 D1을 쓴 이유**: KV는 같은 키에 동시에 쓰면 마지막 쓰기만 남아서
  (last-write-wins) 여러 시청자의 하트비트가 서로를 지운다. D1은 행 단위 UPSERT라 안전하다.
- 들어온 사람: `현재 화면이 재생중입니다. 같이 참여합니다.` (다른 사람이 있으면
  `(N명이 함께 보고 있어요)`를 덧붙인다)
- 이미 보던 사람: 뒤에 누가 들어오면 `새로운 사용자가 접속했습니다`가 잠깐 떴다 사라진다.
- "새 접속" 판정은 **서버가 준 시각**(`now`)을 기준선으로 되돌려 받아 쓴다 →
  시청자 PC 시계가 틀어져 있어도 어긋나지 않는다.

**② 좋아요·댓글 실시간 팝업**

- 이미 있던 댓글 폴링(`?after=<마지막id>`)을 그대로 쓴다. **좋아요 수가 같은 응답에 함께
  오므로**(`likeStateOf`) 추가 API 없이 "숫자가 늘었다 = 누가 눌렀다"로 알 수 있다.
- 새 댓글·좋아요를 화면 우측 상단에 유리 카드로 띄우고 **4.2초 뒤 사라진다**(`livePopup`).
  한 번에 최대 4개까지만 쌓는다(사진을 가리지 않게).
- 폴링 주기를 **닫아둔 동안 20초 → 5초**로 당겼다. 예전 20초로는 "잠깐 떴다 사라지는"
  느낌이 나지 않았다. (열어둔 동안은 그대로 3초)
- 내 댓글은 나에게 팝업되지 않는다(`myCommentIds`로 걸러낸다 — 폴링이 내 글을 되돌려주므로).
  내 좋아요도 버튼 응답으로 `likeCount`를 먼저 갱신하므로 델타에 걸리지 않는다.
- 팝업 내용은 **항상 이스케이프**한다(`esc`) — 남이 쓴 글이 그대로 HTML로 들어가면 안 된다.

**③ 빈화면 모드 (사진만)**

- 아이콘을 새로 만들었다(`#btn-clean`). 누르면 `body.clean`이 붙어 **제목·사진번호·
  촬영일/곡명·하단 진행바·댓글창**이 사라지고 사진만 남는다.
- 아이콘 줄에는 **빈화면 해제**와 **화면 작게(전체화면 토글)** 두 개만 남는다.
- 그 두 아이콘도 **손을 대지 않으면 3초 뒤 사라진다**(`pokeUI` — mousemove·터치·키·휠).
  벽에 걸어두는 전자액자처럼 보이는 게 목적이다.
- ⚠️ 요청에 있던 "오른쪽 상단 날짜"는 **공유화면에 없다** — 시계·날씨(`#ambient-widget`)는
  wepic 메인화면에만 있는 것이다. 공유화면의 날짜는 우하단 `#share-caption`이고 이건 숨긴다.
- 함정: `body.clean .share-actions > * { display: none }`에 **`!important`가 필요했다** —
  `#btn-music`은 JS가 인라인 `style.display`를 직접 넣는데, 인라인 스타일이 보통 규칙보다
  우선이라 !important 없이는 빈화면에서도 음표 아이콘이 남았다.
- 실시간 알림 팝업은 빈화면에서도 뜬다(잠깐 떴다 사라지는 것이라 화면을 계속 가리지 않는다).
  거슬리면 `body.clean .live-popups { display: none }` 한 줄로 끌 수 있다.

**검증** — 브라우저 창이 화면에 표시되지 않아 스크린샷을 찍을 수 없고, 그 상태에서는
Chrome이 **숨겨진 탭의 타이머를 세게 조여** 5초·25초 주기가 제때 돌지 않는다. 그래서
타이머를 기다리는 대신 **같은 코드 경로를 직접 불러** 확인했다.

- 로컬 D1에 "다른 사람"의 댓글·좋아요·접속 행을 심고 → 댓글창 열기(=`loadComments(false)`,
  폴링과 같은 경로)로 팝업 발생을 확인: 좋아요 팝업 + 댓글 팝업이 정확히 1회씩,
  `<script>` 문자열이 `&lt;script&gt;`로 이스케이프됨(팝업 안 `<script>` 0개).
- 팝업 수명: 0·300·1500·3000ms까지 1개, 5000ms에 0개 (LIVE_POP_MS=4200과 일치).
- `beatPresence()`를 직접 호출해 `새로운 사용자 2명이 접속했습니다` 팝업 확인.
- 입장 토스트 문구, presence API 응답(`viewers`/`joined`/`now`) 확인.
- 빈화면: 제목·번호·캡션·진행바 `display:none`, 남은 아이콘이 정확히
  `btn-fullscreen`·`btn-clean` 2개. 자동 숨김은 클래스 토글(3초 뒤 `ui-hidden` 부착 →
  건드리면 해제)과, transition을 끈 상태에서 `opacity:0 / visibility:hidden`을 확인
  (이 창은 프레임을 합성하지 않아 transition이 진행되지 않는다).
- 심은 테스트 데이터는 모두 지웠다.
- **화면을 눈으로 확인하지는 못했다.**

**⑨ 운영 도메인 wepic.kr 연결 — 겪은 함정 4가지**

절대주소를 고정 `BASE_URL`이 아니라 **요청이 들어온 주소** 기준으로 만들도록 바꿨다
(`baseUrlOf`). 덕분에 wepic.kr과 예전 `*.workers.dev`가 **동시에** 정상 동작하고,
이미 나눠준 링크가 죽지 않는다. Host 헤더를 무조건 믿지 않도록 `SITE_HOSTS`·
`*.workers.dev`·localhost일 때만 쓰고 아니면 `BASE_URL`로 되돌아간다.
**데이터 이전은 필요 없었다** — 매니페스트는 상대경로만 담는다.

함정 4가지(전부 실제로 겪음):

1. **Cloudflare Registrar는 `.kr`을 지원하지 않는다.** 다만 이건 *도메인 구매·이전*
   이야기이고, **DNS/CDN(사이트 추가)은 `.kr`을 지원한다**(`log8.kr`이 실제로 Cloudflare
   네임서버를 쓰는 것을 확인). "Transfer"가 아니라 **Add a domain**으로 가야 한다.
2. **가비아의 3차 네임서버(`ns.gabia.net`)가 남아 존이 `pending`에서 멈췄다.** Cloudflare는
   자기가 지정한 2개만 있어야 활성화한다. 공개 DNS로 NS를 물으면 Cloudflare가 자기 존
   기준으로 2개만 답해서 안 보였고, **`whois.kr`(등록소 기록)을 직접 조회해서야** 3번째가
   드러났다. → 진단은 등록소 쪽을 봐야 한다.
3. **`[[routes]]`를 추가하면 Cloudflare가 `workers.dev` 주소를 자동으로 끈다.** 기존 링크가
   전부 404가 됐다. `workers_dev = true`로 되살렸는데, **TOML 최상위 키를 `[triggers]` 뒤에
   적으면 그 섹션의 키로 먹혀 무시된다** — 파일 맨 위로 옮기고 나서야 적용됐다.
4. **`www` → apex 301은 오히려 화면을 망가뜨렸다.** 정적 파일(`/`, `/app.js`)은 Cloudflare
   자산 라우터가 Worker보다 **먼저** 처리해 리다이렉트가 안 걸리는데 `/api/*`만 넘어가,
   www로 열린 화면에서 API 호출이 **교차 출처가 되어 CORS로 전부 막혔다**. app.js가
   `{loggedIn:false}` 폴백을 쓰면서 `availableProviders`가 비어 **로그인 제공자 4개가 전부
   "(준비중)"** 으로 표시됐다. → 301을 걷어내고 **`baseUrlOf`에서 "www."만 떼도록** 바꿨다.
   화면은 www에서도 그대로 뜨고(같은 출처 유지), 내보내는 절대주소만 대표 주소로 통일된다.

> 📌 남은 일: Google·카카오 콘솔에 `https://wepic.kr/auth/callback` ·
> `https://wepic.kr/auth/kakao/callback` 등록(기존 주소는 **지우지 말 것**),
> 네이버·페이스북 키 등록.

### J-17. ✅ 링크 카드 다듬기(흐림 완화·로고) · 아이콘 줄 잘림 수정 (완료, 2026-08-08)

**① 링크 카드 표지가 "무슨 사진인지도 모를 만큼" 흐렸던 것 완화**

J-16 ①에서 만든 흐린 표지(`og.jpg`)는 `blur(44px)`이라 **원본 디테일이 3.6%만** 남았다.
색 덩어리만 보여서 "어떤 자리에서 찍은 사진인지"조차 전해지지 않았다.
→ **`blur(16px)`(`app.js`의 `OG_COVER_BLUR`)로 낮췄다. 디테일 10.3%** — 장면(풍경·구도)은
읽히고 **사람 얼굴은 알아볼 수 없는** 수준이다(데모 사진으로 실측).

- 흐림을 줄인 만큼 어둡게 덮던 값도 `0.3 → 0.16`으로 낮췄다(예전엔 사진이 어두컴컴했다).
- 흐림 반경이 작아져 테두리 비침도 줄었으므로 확대도 `12% → 6%`로 줄였다.
- ⚠️ **이 값은 보안과 맞바꾼 것이다.** PIN을 건 wepic의 표지는 링크만 받은 사람도 보게
  되므로, 더 낮추면 PIN을 건 의미가 옅어진다. 조정할 때는 `OG_COVER_BLUR` 한 곳만 고치면 된다.

**② 카드 제목의 📸 이모지 → 표지 그림에 wepic 로고 직접 인쇄**

`og:title`은 **문자열**이라 그림을 넣을 수 없어 남의 카메라 이모지를 빌려 쓰고 있었다.
→ 제목에서 📸를 빼고(`shareOgTags`), **표지 왼쪽 아래에 wepic 로고 + "Wepic" 워드마크**를
캔버스로 찍는다(`drawWepicBadge`). 로고는 같은 출처 정적 자산(`/icon-192-v2.png`)이라
캔버스를 오염시키지 않고, 못 받아와도 표지는 그대로 만들어진다.

- ⚠️ **전체공유(PIN 없음) wepic에는 로고가 안 붙는다.** 그쪽 카드는 표지가 아니라
  **첫 사진 원본**을 그대로 쓰기 때문이다(J-16 ① 참고). 서버에는 이미지 처리 수단이 없어
  원본에 로고를 합성할 수 없다. 굳이 맞추려면 "선명한 표지"를 따로 만들어야 하는데,
  **PIN은 나중에 걸 수도 있어서** 선명한 표지를 미리 저장해두면 그때 사진이 새어 나간다.
- 카카오는 주소별로 카드를 캐시하므로 **이미 뿌린 링크는 그대로다**
  ([카카오 캐시 초기화 도구](https://developers.kakao.com/tool/clear/og), `/w/` 주소로 넣을 것).

**③ 공유화면 아래 아이콘 줄이 화면 밖으로 밀려 잘리던 문제**

조작 아이콘이 11개(전체화면·빈화면·홈·음악·이전·재생·다음·확대·축소·좋아요·댓글)까지
늘어 폭이 좁은 기기에서는 **마지막 댓글 아이콘이 잘려** 보였다. 두 겹으로 막았다.

1. **좁은 화면(≤600px)에서 먼저 촘촘하게** — 아이콘 30→28px, 간격 6→4px,
   좋아요·댓글 알약의 좌우 여백 10→7px, 왼쪽 여백 16→12px.
2. **그래도 넘치면 줄 전체를 필요한 만큼만 축소** — `fitActionRow()`가 `scrollWidth`(필요 폭)와
   화면 폭을 재서 CSS 변수 `--fit`에 배율을 넣고, `.share-actions`가
   `transform: scale(var(--fit)) / transform-origin: left bottom`으로 줄어든다.
   왼쪽 아래를 기준으로 줄이므로 **위치는 그대로**다.

- `transform`은 배치 폭을 바꾸지 않으므로 `scrollWidth`로 항상 "원래 필요한 폭"을 잴 수 있다
  (축소한 뒤 다시 재도 값이 흔들리지 않는다).
- 폭이 달라지는 순간마다 다시 잰다: 창 크기·회전(회전은 폭 확정이 늦는 기기가 있어 250ms 뒤
  한 번 더), **음악 아이콘 등장/사라짐**, **좋아요·댓글 숫자 자릿수 변화**(0→128), 빈화면 토글.
- 실측(로컬): 375px에서 11개 + 세 자리 숫자 → 필요 348px / 여유 351px로 **축소 없이** 들어가고,
  320px에서는 `--fit = 0.851`로 줄어 오른쪽 끝이 308px(화면 320px 안)에 들어온다.
- wepic **메인화면**의 아이콘 줄(`.photo-actions`)도 같은 이유로 320px대에서 잘릴 수 있어
  같은 방식(`app.js`의 `fitActionRow`)을 함께 적용했다.

- ⬜ **구글 "확인되지 않은 앱" 경고 없애기**를 할 일 **O**로 새로 넣었다(위 O 항목).

### J-20. ✅ "사진 보기"가 비어 보이던 버그 · 인스타 버튼 한 줄 · 문의 안내 (완료, 2026-08-08)

**① 🐞 로그인하지 않으면 "아직 공개된 사진이 없습니다"만 나오던 문제**

먼저 **서버 혐의를 지웠다**: 운영 서버에 직접 물어보니 쿠키 없이도, 방문자 쿠키(`wvid`)만
있어도, 만료된 세션 쿠키가 있어도 `GET /api/public/shares`는 공개 wepic 7개를 200으로
돌려줬다. 즉 로그인 여부와 무관하게 서버는 정상이었다.

원인은 화면이었다. `loadPublicFeed()`가 요청을 **한 번만** 시도하고 실패하면 `catch`에서
목록을 빈 배열로 만든 뒤 "아직 공개된 사진이 없습니다"를 띄웠다 — **"불러오기 실패"와
"공개된 사진이 없음"을 같은 화면으로 취급**한 것이다. 그래서 모바일에서 요청이 한 번만
끊겨도 사진이 있는데 없다고 보였다. J-18에서 `/api/status`에 대해 고친 것과 **같은 결함**이
이 경로에 남아 있었다.

- **3번까지 재시도**(0.4초·0.8초 간격) — 한 번 끊긴 정도는 스스로 회복한다.
- 실패는 **별도 안내 + "다시 시도" 버튼**(`#feed-error`)으로 분리했다. 실패를 "사진 없음"으로
  위장하지 않는 것이 핵심이다 — 그래야 다음에 또 나면 원인을 알 수 있다.
- **요청 번호(`feedLoadSeq`) 가드** 추가 — 홈 진입(`selectPanel(HOME_PANEL)`)과 메뉴 클릭이
  겹쳐 두 번 불릴 때, 늦게 끝난 옛 요청이 새 결과를 덮어쓰지 못하게 한다.
- **검증**(브라우저에서 `fetch`를 가로채 재현): 계속 실패 → 1.2초간 3회 시도 후 실패 안내
  (사진 없음 아님) / **첫 시도만 실패 → 2회째 성공해 카드 정상 표시**(예전 코드가 빈 화면을
  보이던 바로 그 경우) / "다시 시도" 정상 복구 / 느린 성공과 나중 실패가 겹쳐도 나중 요청이
  화면 주인을 유지.
- **남은 불확실성**: 실제 기기에서 그 요청이 왜 실패했는지(순간적인 네트워크 끊김인지 다른
  원인인지)는 재현되지 않아 확정하지 못했다. 다시 발생하면 이제 화면에 "불러오지
  못했습니다"로 뜨므로 구분할 수 있다.

**② 인스타그램 버튼을 공유 버튼과 한 줄로**
